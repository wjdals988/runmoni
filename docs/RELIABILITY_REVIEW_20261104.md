## 문제와 변경

| 실제 경계 | 변경과 보장 범위 |

| 기록 목록 읽기 실패를0건과 혼동 | 목록 오류를 별도 상태로 유지하고 재조회. 마지막으로 읽은 목록과 현재 합계 확정 범위를 구분 |

## UI와 데이터 보존

- 종료 저장 실패의 하단은 단일 ‘저장 다시 시도’로 전환하며 저장 중에는 재제출을 막는다. 본문을 스크롤하지 않아도 필수 행동에 접근한다.
- 진행 러닝의 숫자를 긴 권한/정지 설명보다 먼저 읽게 한다. 저장 오류를 직접 누른 수동 정지로 설명하지 않는다. 큰 글씨의 오늘0회 요약을 짧게 정리했다.
- 홈/러닝/포인트 처리 대상 기록 상세에서 재시도한다. 과거 기록 상세에 현재 진행 중인 러닝의 저장 실패를 해당 기록의 실패처럼 표시하지 않는다.
- Google 기록 요약 백업, 크루 계정 연결/재연결, 기기 GPS·포인트·옷장은 서로 다른 범위다. 새 복구 경로는 **이미 Google에 연결한 크루 프로필과 소속/권한**을 찾는 기능이며 로컬 데이터를 전부 이관하지 않는다.
- DB 스키마·의존성·승인 원본·58개 아이템ID/13슬롯/9탭·보유권/포인트·무료/성별 모델과 기존 서명키를 유지했다. 새 운영 Firestore 규칙은 필요하지 않다. 최신 규칙 게시 완료는 소유자 보고로 유지하며 관리 API/운영 권한 검증과 분리한다.
- 실제 의복은 [기본 의복 마스크 계약](APPROVED_GARMENT_LAYER_PLAN_20261104.md)을 먼저 닫아야 한다. 수영복 마스크를 승인 원본에 재사용하거나 미준비 아이템을 완성으로 표시하지 않았다.

## 상호 검토

기록 담당·계정 담당·UX 담당·원화 기술 검토·독립 출시 검토가 파일 소유권을 나누고 토론했다. 독립 검토에서 발견한 **메모리 지급 원장의 거짓 성공**, **포인트 재시도의 저장 오류 소거**, **검증 전 임시Google 세션을 닉네임 연결에서 채택하는 경합**을 수정하고 회귀 사례를 추가했다. 기록 상세와 전역 상태의 맥락 혼동도 분리했다.

## 검증과 미확인

오프라인/작업자1 JVM76개·실패/오류/skip0, debug lint오류0/경고34와 실제 instrumentation APK 컴파일을 확인했다. [바이너리·소스 해시](app-review/2026-11-04-reliability/debug-build-verification.json). 초기 Android 데이터11개 중10개 통과/1개 초기화 대기 단언 실패(80.606초), UI7개 중5개 통과/2개 옛 문구 선택자 실패(121.157초)를 보존했다. 대기 조건/선택자를 바로잡고, 전체 사진 검토 뒤 종료 실패의 하단 재시도도 보강했다. 기존 러닝 준비/5탭/종료 확인/계정 변경 회귀5개는101.894초에 통과했다. 최종 동일 소스의 Android 데이터12개/76.154초·UI7개/130.406초·시스템 큰 글씨4개/131.86초·로컬demo Firebase SDK1개/30.772초가 모두 통과했다. 반복/선행 회귀를 고유 개수로 합산하지 않는다. [최종 raw/사진/정리](app-review/2026-11-04-reliability/README.md)에 초기 실패·MainActivity의 초기 빈 프레임과 새 대표2장·설정 복원/AVD 종료를 구분해 보존했다. 루트와 독립 출시 검토자가 실제MainActivity 홈/러닝2장을 직접 확인했다. 저장·지갑IO/최신 프로필 보존과 RECOVERY/IDLE의 거짓 기록 알림 제거도 보강했다. 공개 서명 APK와 운영 대시보드 검증은 실제 게시 뒤 별도로 기록한다.

현재까지 실제 휴대폰·Google 대화형 인증/실제 자격 충돌·다른 기기의 Google 크루 복원·운영 Firebase 쓰기/권한과 야외 GPS/배터리는 미검증이다. 정책 테스트·demo SDK·합성 상태 UI·로컬HTTP·공개 서명 APK의 실행은 각각 다른 근거다. 수치 통과를 사용자 시각 승인으로 바꾸지 않는다.
