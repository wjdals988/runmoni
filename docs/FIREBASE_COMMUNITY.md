# 무료 Spark 크루·파티 연결

2026-10-30 사용자는 별도 호스팅 계정 없이 기존 Firebase를 사용하는 방향을 선택했다. 현재 기본 구조는 **크루가 최상위, 파티가 그 크루 안에서 생성·삭제되는 하위 모임**이다. `runmoni-3c08e`의 Authentication 익명 프로필 + Firestore 크루·파티/멤버/실시간 채팅을 사용한다. **Cloud Functions·Render·유료 디스크·Blaze 결제 연결이 필요하지 않다.** Spark 무료 한도를 사용하며 프로젝트의 실제 요금제는 소유자가 확인한다.

## 0.3 크루·파티 변경 시 추가 게시

최초 설정1~5번 완료는 보존한다. 이후 사용자 요청으로 **크루 아래 파티 생성/참가와 파티 삭제**를 추가하면서 Rules 계약이 바뀌었다.0.3 APK의 새 삭제 기능에는 이번 main의 [전체 규칙](../firebase/firestore.rules)을 같은 프로젝트 `(default)`의 Rules 편집기에 다시 붙여넣고 게시해야 한다. 기존 설정 JSON/지문/Secret/서명키를 다시 등록하거나 유료 요금제로 바꿀 필요는 없다. 인덱스 정의는 변경하지 않는다.

이 클라우드에는 Firebase 관리 계정 연결이 없어 **이번 운영 Rules 게시를 대신 수행하지 않았다.** CI의 구성/public read 준비는 운영 삭제 권한 규칙의 버전을 확인하지 않는다. 규칙 demo 검증과 실제 운영 삭제/Google 로그인을 구분한다.0.3 검토 APK에서 테스트할 때는 최신 규칙 게시 → 크루 생성/가입 → 소속 파티 생성/참가 → 주최자/크루장의 **파티 삭제 → 삭제** 확인 → 다른 참여자의 목록/채팅 차단을 확인한다. 삭제는 목록과 참가/대화 접근을 종료하는 보존삭제이며 대화 문서/러닝 원본을 일괄 파괴하지 않는다.

## 소유자가 한 번 연결하는 순서

**2026-11-02(한국 시간) 소유자 확인:** ‘5번도 완료됐음 굳굳’ 응답으로 아래1~5번 설정 완료를 보고받았다.1~4번은 앞서 완료 보고/CI 구성 검사를 받았고5번은 소유자 콘솔 완료 보고다. 당시 공개0.2.1 APK에는 설정이 포함돼 있어 색인 완료만으로 다시 빌드하거나 설정 파일/Secret을 다시 보낼 필요가 없었다. **이후 추가한0.3의 계층/삭제 기능에는0.3 APK와 위 새 Rules가 필요하다.** 이전0.2.1의 출처는 `c6bc5739746fe176269fed3bf64360417b50875e`로 보존한다. 실제 휴대폰·Google 로그인·운영 크루/파티 쓰기는 별도 미검증이다. [이어서 진행할 작업](DEVELOPMENT_CONTINUATION.md)을 따른다.

아래는 최초 연결/향후 설정 변경 때의 참고 절차다. Android 설정은 GitHub Secret으로 CI에 한시 주입하며 클라우드에 관리 계정을 연결하지 않았다. 비밀번호·서비스 계정키·토큰·서명키는 채팅으로 보내지 않는다.

1. [Authentication 제공자](https://console.firebase.google.com/project/runmoni-3c08e/authentication/providers)에서 **익명(Anonymous)**과 **Google**을 켠다. 익명은 크루 닉네임, Google은 개인 기록 요약 백업에 사용한다. 지원 이메일은 본인이 선택한다.
2. [Android 설정](https://console.firebase.google.com/project/runmoni-3c08e/settings/general)의 `com.runmoni.app`에 현재 보관 키 지문을 추가한다. SHA-1 **`19:2A:7E:29:84:3C:90:21:0E:ED:D1:37:3A:78:D4:DA:77:F0:97:73`**, SHA-256 **`A2:13:59:C6:57:F6:79:7F:5F:B8:22:9C:30:98:E4:8B:C7:2A:45:F9:D2:52:69:F8:D4:1F:F5:12:24:65:DF:4A`**. 등록 후 새 `google-services.json`을 받는다. 이전 키 지문은 지우지 않아도 된다.
3. 파일을 로컬 저장소 `.secrets/firebase/google-services.json`에 두고 아래 PowerShell로 **Android 설정만** 클립보드에 복사한다. [GitHub Actions Secret 추가](https://github.com/wjdals988/runmoni/settings/secrets/actions/new)에서 이름 **`RUNMONI_FIREBASE_ANDROID_CONFIG_BASE64`**, 값에 붙여넣어 저장한다. GitHub CLI는 필요 없다. 사용 후 클립보드를 지운다.

```powershell
Set-Clipboard -Value ([Convert]::ToBase64String([IO.File]::ReadAllBytes((Join-Path (Get-Location) '.secrets/firebase/google-services.json'))))
```

4. [Firestore 규칙](https://console.firebase.google.com/project/runmoni-3c08e/firestore/databases/-default-/rules)에 [firestore.rules](../firebase/firestore.rules) **전체**를 붙여넣고 게시한다. 기존 본인 요약 보호 규칙도 포함돼 있다. 전체 허용 규칙을 쓰지 않으며 다른 프로젝트에 덮어쓰지 않는다.
5. [Firestore 색인](https://console.firebase.google.com/project/runmoni-3c08e/firestore/databases/-default-/indexes)에 컬렉션ID **`communityRooms`**, 컬렉션 범위의 복합 색인을 만든다: `visibility` 오름차순, `kind` 오름차순, `createdAt` 내림차순. [정의](../firebase/firestore.indexes.json)와 같으며 완료될 때까지 기다린다. 기본DB `(default)`가 없다면 Spark/Standard·프로덕션 모드로 먼저 생성한다.

Firebase 크루·파티에는 외부 서버 주소와 `RUNMONI_API_URL`이 필요하지 않다. 기본 backend는 `firebase`다. 기존 HTTP 파일럿은 고급 테스트 설정으로 보존하며 Firebase 인증 토큰을 그 서버에 보내지 않는다.

## 새 APK와 휴대폰 확인

[Android release candidate](https://github.com/wjdals988/runmoni/actions/workflows/android-release.yml)의 main, `mode=audit, profile=review`로 먼저 점검한다. 실제 보관 DER·Android 프로젝트/패키지/Web OAuth/현재 SHA-1·공개 메타데이터의 REST 읽기를 검사한다. 계정 생성·개인 읽기·크루/파티 쓰기는 하지 않는다.

`ready=true`는 **현재 인증서·Android 설정·공개 목록 읽기 준비**다. `anonymousProviderVerified`, `publicRoomWritesVerified`, `physicalDeviceVerified`, `interactiveGoogleLoginVerified`는 CI에서 false다. `mode=stage-draft, profile=connected`는 구성 누락 시 APK 빌드 전에 중단한다. 서명 키4개는 유지하고 Android 파일은0600으로 주입해 종료 시 삭제한다. 원문 설정/API 키/토큰은 artifact·로그·Git에 넣지 않는다.

게시 검증된0.3 APK → 크루 탭 → 닉네임/성인 확인 → **크루 만들기** → 크루 상세의 **파티 만들기** → 다른 휴대폰에서 크루 가입/파티 참가 → 채팅/공지 → 정원/역할 → **파티 삭제** 순서로 확인한다. 설정 → 연결·휴대폰 점검에서 Firebase 목록 응답과 Google 계정 선택/온라인 세션 응답을 각각 확인한다. [공유 범위](CONNECTED_DEVICE_CHECKS.md)를 따른다. APK 서명·버전/code·해시·출처를 확인한 뒤 공개 피드와 대시보드를 바꾸며 과거0.2.0/0.2.1 출처·자산은 보존한다.

### 휴대폰에서 확인하는 순서

1. 이번 계층/삭제 기능을 확인하려면 **게시 검증을 마친0.3.0-dev/code12** APK를 설치한다. 대시보드/릴리스에서 실제 버전이0.3인지 먼저 확인하며,0.3 미게시 상태의 기존0.2.1 다운로드에 새 기능이 들어 있다고 해석하지 않는다.0.1.6/0.2.0/0.2.1과 동일한 보관 키를 사용해 기존 앱을 제거하지 않고 업데이트를 시도한다. 설치 실패 시 오류 문구를 확인하고, 기록을 보존하려면 오류 해결 전에 임의로 앱을 삭제하지 않는다.
2. 홈 오른쪽 위 설정 → **연결·휴대폰 점검** → **서버 연결 확인**을 누른다.0.3의 정상 응답은 ‘Firebase 크루·파티 목록을 서버에서 확인했어요’다. 목록0개는 오류가 아니다. 연결 설정이 없는 빌드라고 표시되면 설치 버전/구성 포함 여부를 확인한다. 목록 실패 시 인터넷과 소유자 콘솔의 최신 규칙 게시·기존 색인을 확인한다. 이 응답은 새 삭제 Rules가 게시됐다는 증거가 아니다.
3. 같은 화면의 **Google 계정 선택·로그인**으로 계정을 선택한다. ‘이번 실행에서 계정 선택·로그인 완료’를 확인하고 **계정 서버 응답 확인**도 누른다. 이것은 기록 요약 백업 성공과 별개다. 백업은 저장한 기록 상세에서 따로 실행한다.
4. **크루** 탭 → **크루 만들기**를 누른다. 필요하면2~24자 닉네임과 성인 확인으로 크루 프로필을 연결하고 이름·지역 등 폼을 입력한다. 크루 상세의 **파티** 탭에서 **파티 만들기**로 일정을 만든다. 파티는 크루 멤버만 만들 수 있으며 새 독립 파티 생성은 지원하지 않는다. Google 요약 계정과 크루 닉네임은 별도다.
5. 다른 휴대폰에도 같은0.3 APK를 설치하고 **다른 닉네임**으로 크루를 찾는다. 미가입자도 공개 파티 메타데이터를 볼 수 있다. **크루 가입하기** 후 **파티 참가하기**, 또는 파티 상세의 **크루 가입하고 참가**를 선택한다. 후자는 크루 가입 → 파티 참가 순서이며 정원 등으로 파티 참가가 실패해도 이미 완료된 크루 가입을 되돌리지 않는다. 두 기기의 크루/파티 채팅·공지 권한·정원을 확인하고, 크루 탈퇴 뒤 하위 파티의 기존 참가자/주최자/DJ도 대화에 접근할 수 없는지 확인한다.
6. 주최자 또는 부모 크루장 계정에서 파티 상세 → **파티 삭제** → 확인창 **삭제**를 누른다. 다른 참여자의 목록을 새로고침해 파티가 사라지고 재참가·채팅이 차단되는지 확인한다. 일반 멤버/다른 크루장은 삭제할 수 없어야 한다. 삭제는 문서를 보존하는 종료 처리이며 크루나 개인 러닝 기록을 지우지 않는다. 삭제한 파티를 새로 생성할 수 있는지도 확인한다.
7. 설정 → **연결·휴대폰 점검**의 **점검 결과 공유**로 실제 확인한 항목만 공유한다. 수동 확인은 자동 검증과 구분된다. 실패 시 어느 버튼에서 나온 어떤 오류인지 알려주되 비밀번호·토큰·설정 JSON·개인 GPS 경로는 보내지 않는다.

익명 크루 프로필은 Google 요약 계정과 별도다. **연결 해제·기기 변경·재설치 후 참여 내역/크루장 권한은 복구되지 않는다.** 해제 전 앱에서 다시 확인한다. Google 연결로 익명 프로필을 복구/합치는 기능은 아직 없다. 파티는 주최자/크루장이 명시적으로 삭제하며 시작 시각만으로 자동 만료시키지 않는다. 삭제 뒤 대화 문서와 메타데이터 tombstone은 보존되지만 앱에서 다시 참가하거나 대화를 읽는 복구 기능은 제공하지 않는다.

## 권한·비용 경계

- `communityProfiles/{uid}`는 본인만 읽는다. 요약은 기존 `/users/{uid}/runSummaries`를 유지한다. 지갑/보상/원본 GPS/임의 경로 쓰기는 계속 거부한다.
- 전역 탐색은 종류별 최대3페이지×50문서를 읽어 삭제된 항목을 제외한 최대50개와 본인 참여/필요한 부모 크루를 보완한다. 전체 DB 검색이나 모든 파티의 완전한 목록을 보장하지 않으며 삭제 데이터가 많으면 전역 탐색 범위 밖의 파티가 있을 수 있다. 공개 메타데이터에 제목·설명·지역·페이스·일정·정원·인원·소유자UID가 포함되며 이메일/계정 프로필/개인 GPS는 넣지 않는다.
- 선택한 크루 상세는 전역 파티50개를 단순 필터하지 않고 그 크루의 `active` 파티를 별도 서버 조회한다. `visibility/kind/crewId/status` 동등 필터, 최대50개, 정렬 조건 없이 읽은 결과를 앱에서 시작 시각순으로 정렬한다. 삭제 tombstone은 이 조회의50개 자리를 소비하지 않는다. 반환된50개가 전체 크루 일정 중 가장 이른50개라는 뜻은 아니며 추가 페이지 UI는 아직 없다. 본인이 이미 참여한 파티는 별도로 보완한다. 새 정렬 복합 색인 정의는 추가하지 않았고 실제 운영 조회/권한은 별도 확인한다.
- 생성/가입/탈퇴는 인원·본인 참여 링크·멤버3문서를 원자적으로 바꾼다. 파티 생성/참가에는 유효한 부모 크루의 현재 멤버여야 한다. 정원 경합/카운터 단독 위조·임의 소유권 변경을 차단한다. 크루장은 크루를 탈퇴할 수 없고 주최자는 파티가 유지되는 동안 참가를 취소할 수 없다. 새 UI의 종료 동선은 주최자/부모 크루장의 **파티 삭제**이며 과거 `cancelled` 데이터는 종료 상태로 처리한다.
- 파티 삭제는 `status=deleted` tombstone으로 보존하고 목록·새 참가·멤버 목록/대화 접근·새 메시지를 차단한다. 삭제 후 본인 참여 링크/멤버/인원은 원자 정리할 수 있고 마지막 주최자도0명까지 정리한다. 본 조회/삭제 성공 뒤 본인 항목만 최대5개·별도1초 예산으로 정리하며 일시 실패/예산 만료는 다음 새로고침에서 재시도한다. 다른 사람의 비공개 프로필을 일괄 수정하지 않는다.
- 채팅은 현재 멤버의 작성자·닉네임·서버 시각·멤버 속도 제한 문서를 함께 검증한다. 파티 대화는 부모 크루 소속도 유지해야 한다. 메시지1~1000자/2초 간격, 크루/파티 생성10초 간격, 프로필 참여 링크 최대100개를 유지한다. 평생20회 생성 제한은 제거했고 누적 카운터를0~1,000,000으로 제한하며 단독 재설정/위조는 거부한다. 공지는 크루장/주최자/DJ/부모 크루장 권한 외에도 해당 대화의 현재 참여·부모 크루 조건을 충족해야 한다.
- 목록은 수동/작업 후 갱신, 멤버는 관리 화면을 열 때 조회한다. 채팅은 열어둔 크루/파티 대화만 구독하며 닫기/로그아웃 때 해제한다. 캐시를 서버 연결 성공으로 표시하지 않는다.
- 무료 한도는 프로젝트 전체에서 공유된다. 익명 계정 남용·대량 공개 조회를 완전히 막는 구성은 아니다. App Check·계정 복구·운영 신고/정리·부하/배터리 검증은 후속 범위다. Firebase 크루·파티는 음성 통화·음악 방송·실시간 GPS 공유를 지원하지 않는다. 개인 러닝/포인트/옷장/GPX는 기기에 보존한다.
