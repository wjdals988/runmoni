## 이번 검토의 판단

잘못된 미니미를 유지하면서 꾸미기를 완성된 것처럼 보이는 문제가 가장 먼저다. 승인 기본형으로 복구하되, 아직 그리지 않은 의상으로 포인트를 쓰지 않게 한다. 보유권이나 저장된 선택을 삭제하지 않는다. 다음 원화 작업은 기존 얼굴·체형·전신 프레임을 기준으로 의복만 바꾸고, 자연스러운 7→0 전환과 여자 화면 왼쪽 팔을 실제로 검토한다.

업데이트 알림은 우상단의 실제 설치 버전명/점 → 설치/새 버전과 확인 → 사용자 선택 다운로드로 연결한다. 현재 공개 피드는 검증 전 테스트용으로 게시된0.1.6-dev/code7을 가리킨다. 개발0.1.7/code8·0.1.8/code9는 아직 미게시이므로 피드를 올리지 않는다. 업데이트 확인 기능이 없는 과거 APK에는 새 코드가 소급 설치되지 않는다.

대시보드는 APK 바이너리를 저장하는 곳이 아니다. [대시보드 게시 규약](https://github.com/wjdals988/mydashboard/blob/main/docs/release-automation.md)에 따라 앱 저장소의 검증한 GitHub Release URL/버전/code/크기/SHA256만 저장한다. 사용자가 승인한 새 키는 GitHub의 동일 서명 설정을 재사용하고 다시 생성하지 않는다. debug APK를 공개 다운로드로 대체하지 않는다. 기존0.1.5 APK의 sourceRevision `75c39ca900b140cfb02c1a47807a5955c8b8db7f`, 공개0.1.6의 `9dd409f00bab54f9ebf7f0ce3f85f36ff54b1750`도 바꾸지 않는다.

## 매 작업 묶음의 기록

1. 가장 높은 미완료 항목 중 현재 환경에서 진행할 수 있는 작업을 선택한다.
2. 기능 변경·데이터 호환·실패/복구를 검증한다. 테스트와 사용자 시각 승인을 구분한다.
3. awesome-design-md 참고와 UI/UX·작은 화면/큰 글씨 결과를 DESIGN/CHANGELOG에 기록한다. 미니미는 Aseprite 레이어/프레임 개념과 비교하고 실제 사용 여부를 밝힌다.
4. 커밋·푸시·PR URL, APK의 실제 버전/해시/서명/출처, 업로드/대시보드 수행 여부를 기록한다.
5. 막힌 기능은 차단 근거와 필요한 조건을 남기고 나머지 작업을 계속한다. 실행하지 않은 검증·업로드·배포를 완료라고 표시하지 않는다.
