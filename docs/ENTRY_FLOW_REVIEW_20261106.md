# 첫 로그인 선택 검토 — 2026-11-06 한국 시간

OS 스플래시 뒤에 신규 사용자의 Google/게스트 선택을 두고, 선택 이후와 기존 사용자는 앱으로 바로 들어간다. 첫 실행의 선택은 계정 상태와 별도로 저장하며 오프라인·세션 만료가 기기 러닝을 다시 잠그지 않게 한다.

|상황|처리|

## 계정과 데이터

Google 버튼은 기존 `runmoni-cloud`의 Google 인증을 재사용한다. Google 계정은 기록 요약 백업에 사용하지만 업로드는 여전히 수동이다. 기기 GPS 경로·포인트·옷장 전체 복원을 약속하지 않는다. 크루의 `runmoni-community` UID·연결·복원·성인 닉네임 동의는 해당 기능에서 별도로 선택한다.

게스트 선택이나 첫 Google 인증으로 크루 연결·프로필 생성·권한 이관·요약 업로드·위치 공유를 연쇄 실행하지 않는다. 입장 여부는 크루의 `signedIn`/`communityGuest`나 기존 `cloud.uid` 존재로 판정하지 않는다. SDK 계정 선택 취소가 정상 함수 반환이나 기존 UID로 나타나더라도 이번 작업의 성공 결과가 아니면 입장 선택을 완료하지 않는다.

## 상호 검토

account_link_reliability는 두 인증 저장소·UID 보존·명시적 성공·늦은 작업·재생성·저장 실패를, consumer_copy_ui는 최초/재실행·게스트 접근·문구·큰 글씨·안전 영역을 검토했다. 앱 시작 자체가 `publicLocation`과 Room을 만들므로 prefs나 DB 파일의 존재만으로 기존 사용자를 판별하지 않는 점을 채택했다. 기존 설치 업데이트 정보·로컬 프로필과 명시적 선택을 구분한다.

awesome-design-md 고정 revision `fcc70284932276d085f01ef9f83edde90b1258cb`의 Apple 제3자 분석에서 행동 우선·장식 절제를 참고했다. 기존 로고·서체·색과 이미 포함된 SDK의 공식 Google G를 사용했다. 새 의존성·원화·렌더·서명키·Firebase 규칙 변경은 없다. 내부 검토는 사용자 시각 승인과 다르다.
