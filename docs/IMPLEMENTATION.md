# Runmoni 구현 결정 / 2026-10-13

2026-10-14 추가 결정: 공용 계정·DB는 Firebase 무료 Spark로 확정했습니다. 첫 단계의 Google 로그인·본인 요약 수동 백업은 [별도 구현 기록](FIREBASE_IMPLEMENTATION.md)에 설명합니다. 개인 GPS 원본은 Room, 크루·파티·DJ·보상은 검증된 로컬 API에 유지하며 Firestore adapter로 단계적으로 이전합니다. 기존 Supabase SQL은 현재의 운영 계획이 아니라 검토 이력입니다.

## 수락한 방향

Android 10(API29) 이상 우선. 5개 탭으로 중심 행동을 고정하고 웹으로 GPS 신뢰성을 대체하지 않습니다. 첫 검증은 외부 계정 비용 없이 로컬 환경과 성인 지인으로 진행합니다. 추후 미성년자와 대중 서비스는 별도 계정·위치 정책과 본인 확인을 갖춰 확장합니다.

| 탭 | 책임 | 핵심 행동 |
|---|---|---|
| 홈 | 개인 요약·다가오는 일정 | 기록·러닝·파티로 이동 |
| 탐색 | 실제 지도·위치 공유 동의 | 정밀 위치를 공유할 대상·지속시간 확인 |
| 러닝 | GPS 세션·오디오 조작 | 시작/일시정지/재개/확인 후 종료 |
| 크루 | 가입·멤버·공지·채팅·파티 | 크루 만들기, 파티 참석, 음성방 연결 |
| 나 | 기록과 미니미·설정 | 일/월/년 확인, GPX, 구매·장착 |

크루와 파티에 각각 채팅/공지/음성 room scope를 둡니다. 파티 주최자는 취소할 수 있고 크루장은 DJ를 지정합니다. 그룹장과 DJ에 방송 권한이 있으며 방당 1개 음악 세션만 허용합니다. 음악과 음성은 별개 트랙으로 0~100% 음량을 제공합니다.

## 이번 기술 검증의 경계

1. GPS 저장은 foreground service+Room. 1초 위치 요청, 1초 상태 저장. 정확도 30m 이내, 이동 속도 8m/s 이하, 연속점 공백 60초 이하만 거리 계산.
2. 공백을 pause/recovery segment로 구분하여 건너뛰는 직선을 거리와 GPX에 넣지 않음. 현재 페이스는 최근 10개 이동 구간, 평균은 전체 활동시간/거리.
3. 러닝 중 wake lock을 사용하여 타이머와 저장 흐름 유지. 배터리 효율은 아직 측정하지 않았으며 절전 최적화 판단은 기기 검증 후 수행.
4. 크루·파티 API는 FastAPI+SQLite로 기능 검증. 정원·마일리지 트랜잭션을 테스트. Supabase RLS/SQL은 이관 준비 단계이며 실행 검증 전 적용하지 않음.
5. 위치 공유는 성인 초대 코호트에 한정. 15초 갱신/45초 만료. 전체 공개 지도·미성년자 지도·그룹장 대표 마커 집계는 아직 별도 후속 구현.
6. 음성 LiveKit, 음악 Android Opus128kbps→Python bridge→LiveKit 음악 트랙. 별도 음량을 우선 검증. 외부 앱 6종은 각각 캡처 가능 여부를 시험해야 함.
7. 마일리지는 1km=100P, 20개 아이템 중 무료5종. 실제 유료 결제는 제품 검증 후 검토.

비관적 검토: GPS+지속 음성+음악 인코딩을 동시에 쓰면 배터리·발열·블루투스 통화 모드 품질이 제품 성패를 결정합니다. UI와 단위 테스트만으로 이를 보증할 수 없습니다. 초대코드 로그인은 계정 복구가 없어 대중 계정 시스템으로 사용할 수 없습니다.

긍정적 활용: 개인 기록과 미니미를 서버 없이 시험할 수 있으므로 친구들의 실제 사용 로그를 먼저 확보할 수 있습니다. 파티와 DJ의 효과를 확인한 뒤 클라우드 비용과 꾸미기 BM을 결정할 수 있습니다.
