# 런모니 다음 개선안 — 서비스 벤치마킹

기준: 2026-11-03 한국 시간, 공개 앱0.3.1-dev/code13. 이 문서는 **다음 구현 범위를 고르기 위한 제안**이다. 경쟁 앱을 직접 설치해 사용성 실험을 한 결과가 아니라 공식 소개·도움말·플랫폼 문서, 현재 런모니 코드와 기존 실제 Android 캡처를 대조했다. 개선율·유지율·개발 기간은 측정하지 않았다.

핵심 방향은 **신뢰할 수 있는 러닝 기록 + 실제로 꾸밀 수 있는 미니미 + 지속되는 크루와 유동적인 파티**다. 화면 전체를 새 테마로 교체하기보다 이 세 가지가 이어지는 사용 흐름을 완성한다.

## 현재 상태를 출발점으로 삼기

- 사용자 ‘오케이 반영 완료’를 **최신 Firestore 규칙 소유자 게시 완료 보고**로 기록한다. 같은 규칙의 게시를 다시 요청하지 않는다. 관리 API의 배포 버전 확인·운영 권한/쓰기·실제 휴대폰·Google 로그인 성공은 별도 미검증이다. 과거 CI/readiness JSON의 false는 바꾸지 않는다.
- PR21/22와 대시보드 PR14의0.3.1 배포는 완료됐다. 공개 피드 실제 응답까지 확인한 [PR22 최종 댓글](https://github.com/wjdals988/runmoni/pull/22#issuecomment-6597694849)로 R04를 닫는다. 이번 계획 문서는 APK 출처·버전·업데이트 피드·운영 다운로드를 변경하지 않는다.
- 이미 있는 것: 자동/수동 일시정지, 기본 중단 복구, Room 기록·GPX 내보내기, runId별 포인트 지급 원장, 크루→파티·참가/취소/삭제, 채팅, 남녀 전환·전58아이템0P 선택 저장,9탭/13슬롯, 홈 실제 합계/예정 파티/최근 기록, 목록 상태 구분, 작은 옷장 선택 타일. 이를 새 기능으로 다시 제안하지 않는다.
- 남은 큰 차이: 많은 의상은 선택만 저장되고 기본형이 표시된다. Google 요약 계정과 익명 커뮤니티 UID는 분리되어 있으며 로그인만으로 원본GPS·포인트·옷장·크루 권한이 모두 복원되지 않는다. 검색은 현재 불러온 유한 목록을 필터한다.
- 기존 캡처는 AOSP API29/TCG의 debug MainActivity·localhost HTTP 데이터다. 공개 서명 release·운영 Firebase·실제 휴대폰 캡처로 표시하지 않는다. 근거는 [실행 기록](app-review/2026-11-03-context-ui/README.md)에 있다.

## 우선순위 의미

- **P0:** 기록·계정·조작 신뢰성에 직접 영향을 주는 확인/수정. 실제 실패가 발견되면 우선 대응한다.
- **P1:** 사용자가 기대하는 꾸미기와 크루/파티 사용 흐름을 완성. 독립 작업은 실기기 결과 대기 중에도 진행한다.
- **P2:** 기반이 확인된 뒤 반복 사용·설치/운영 효율을 개선. 측정·정책 정리는 먼저 할 수 있다.

## 구현 순서 제안

1. **신뢰 기반:** B01–B03 + D01–D03·D09의 정확한 상태 안내. 휴대폰 결과 대기 중에도 저장 오류 주입·계정 정책을 진행한다.
2. **런모니 정체성:** B04/D07을P1 첫 독립 묶음으로 고정한다. 모든58종을 한 번에 약속하지 않고 실제로 갈아입는 소수 조합을 승인받는다. 실기기 검증 대기로 이 작업 전체를 멈추지 않는다.
3. **함께 달리기 완주:** B05–B09 + D04–D06·D10. 크루 운영→맞는 파티 찾기→참가→일정 변경/대화→완료까지 연결한다. 신고/차단은 공개 확대보다 먼저다.
4. **다시 사용할 이유와 효율:** D08·D11 + B10–B12. 날짜 이동/기록 이해→주간 목표→코스 재사용 순으로 작게 확장하고 실제 사용 결과를 보고 범위를 늘린다.

앱 실행·오류 주입·권한 검증·실기기 관찰·사용자 시각 승인을 따로 기록한다. 비교 가능한 과제는 ‘파티를 고르고 참가/취소’, ‘옷을 바꾸고 저장’, ‘기록을 찾고 백업 상태 설명’처럼 정하고, 완료/막힘·오조작·누락을 관찰한다. 표본 없이 만족도·전환율·작업시간 개선 수치를 만들지 않는다.

## 이번에 앞당기지 않을 범위와 상호 검토

- 글로벌 피드·공개 순위·배지 확대·강제 연속 달리기: 기록 신뢰성, 충분한 실제 활동, 운영/신고 체계가 먼저다. 가짜 러너·게시물·추천/인기 수를 넣지 않는다.
- 새 팔레트·전용 폰트·반복 카드/칩·이모지로 전체 교체: 이미 정리한0.3.1의 표면을 다시 만드는 대신 위계·상태·흐름을 검수한다. 필요한 숫자 패널·오류 구획까지 제거하지 않는다.
- 실시간 음성/음악·라이브 위치·웨어러블/Health Connect·AI 코칭: 권한·실제 데이터 흐름·인프라/권리/비용 조건을 확인한 뒤 별도 범위를 잡는다. 지도·음성은 기존F06 후속 검증을 보존한다.
- 계정 연결을 모든 데이터 백업으로 포장하거나 미준비 의복에 가짜 미리보기 제공: 기능 보장과 원화 승인 범위를 그대로 드러낸다. 원본 몸통/팔다리를 다시 만들어 거절된v0.4 조립을 반복하지 않는다.

디자인/기능 담당의 독립 검토 후 반대 관점으로 다시 확인했다. ‘기록 신뢰성을 먼저’라는 의견은 채택하되 **소유자 응답 대기로 미니미 개발까지 미루는 순서는 기각**했다. 필터 과잉·설정 깊이 증가·통계 카드 증설도 기각했다. 미니미의 제품 비중은 유지하고 실제 의복 연결을 우선하며, 계정 복구와 UI 설명을 분리한다. 공식 문서가 지원하는 동작과 런모니 운영에서 검증된 결과를 구분한다.
