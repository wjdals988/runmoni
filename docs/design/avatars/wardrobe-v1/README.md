# 승인 원본 위의 고정 프레임 의복·장비 검토

승인된 v0.3 전신 원본은 수정하지 않았다. 원본 SHA256은 `f9035f29ced0c7ba513dfe24cb727410a7204dc482fc457e806c7a9b3cdbfa65`다. 남녀2행×8프레임의 몸·머리·팔다리 위치를 그대로 사용하고 의복 coverage와 장비만 덧입힌다. v0.4 거절된 몸 리그나 v0.5 미승인 수영복을 사용하지 않는다.

이 문서의 `host-*.png`는 **호스트 렌더 출력**이며 Android 앱 스크린샷·사용자 원화 승인이 아니다. 실제 Android 근거는 [앱 검토](../../../app-review/2026-11-04-closet-redesign/README.md)에 별도 기록한다. 제품 옷장에는 이 비교 자료를 여는 메뉴가 없다.

## 현재 연결 범위

|슬롯|실제 렌더에 연결한 ID|남은 원화|
|---|---|---|
|헤어·얼굴·세트·양말|각 기본0|나머지 새 형태|
|모자|0/3 헤드밴드|1 캡/2 선바이저|
|상의|0 기본/1 반팔/2 긴팔/3 지퍼 상의|4 브라탑/5 크롭티|
|하의|0 기본/1 러닝 타이츠|2~5 짧은 하의/바이커/스플릿|
|신발|0 기본/1 코랄/2 블루/3 골드|기존 실루엣의 소재 팔레트 변화|
|이어폰·선글라스·워치·벨트·수분 조끼|각0~3|사용자 시각 검토/추가 형태|

총58개 ID 중 기본13개와 비기본23개, 합계36개가 표시된다. 나머지22개의 기존 ID·보유권·저장 선택은 삭제하지 않고 새로 선택할 수만 없게 한다. 모든 아이템0P 정책과9분류/13슬롯·액세서리별 점유/세트 해제 규칙은 유지한다.

원본 여자 기본형은 반팔·긴 바지이고 남자는 싱글릿·쇼츠다. 남자 타이츠는 기존 쇼츠 아래 드러난 다리에 덧입히며, 여자 타이츠는 기존 긴 바지의 소재 팔레트를 바꾼다. 숨어 있는 피부를 추정하거나 기본형 차이를 같은 옷으로 위장하지 않는다. 새 수영복·헤어·표정과 전체58종의 원화는 미완료다.

## 자료와 순서

`build-wardrobe-coverage.py`는 원본별 어깨/팔꿈치/손목 좌표와 독립 손 보호 폴리곤에서 명시적 coverage 데이터를 만든다. 원본 파일에는 쓰지 않는다. 앱은 색상/피부를 추정하지 않고 체크한 PNG 라벨만 읽는다. R은 반팔1/긴팔2/다리4 bit flags, G는 명암, B는 소매 끝 flags, A255만 유효하다. 손 보호와 coverage의 교집합은0이어야 한다. manifest의 원본·coverage·손 보호 SHA와16셀 완전성을 런타임에 확인한다.

렌더 순서는 원본 전체 프레임 → 기존 의복 천 팔레트 → 명시된 새 소매/다리 coverage → 천 영역에 제한한 수분 조끼·벨트 → 워치·헤드밴드·귀 장비·선글라스다. 몸 장비는 기존 천 라벨에만 그려 전경 팔/손과 새 소매를 덮지 않는다. 선글라스·머리/귀 장비는 해당 부위를 의도적으로 가리므로 모든 얼굴 픽셀이 그대로라는 주장을 하지 않는다. 얼굴/체형을 교체하는 동작은 없다.

색상0은 선택한 아이템의 기본 팔레트다. 1~5는 민트/코랄/블루/퍼플/골드로 기존 저장 계약을 유지한다. 새 품목을 선택하면 그 부위만 기본색0으로 착용한다. 같은 품목을 다시 누르면 현재 선택색을 유지하고, 다른 부위의 색·장비·성별·포인트/보유권은 보존한다. 예를 들어 퍼플로 바꾼 신발에서 코랄 신발을 선택하면 코랄 고유색을 바로 보여준다. 저장/이관의 순수 withItem 계약은 기존 색상을 보존하고, 명시적인 옷장 동작 withSelectedItem만 해당 기본색을 적용한다. 원본 alpha와 흰 밑창/줄은 유지한다.

## 검토 결과와 경계

- 호스트 의복864사례와 실제 production Kotlin 장비272사례에서 입력/alpha·허용 영역 바깥 불변, 장비의 전경 팔 가림을 검사했다. 조합 전체나 모든 의미상 피부를 자동 판별한 결과는 아니다.
- 독립 검토에서 어깨 삼각형·팔꿈치 틈·굽힌 앞손 착색·타이츠 발목 누락·높은 헤어핀 같은 밴드를 발견했다. 팔별 coverage 연결/둥근 팔꿈치/독립 손 lock/다리 범위/밴드 위치·두께를 수정해 남녀16셀 정지 출력에서 재검토했다.
- 검토자는 최신 정지 출력에서 추가 차단 문제를 찾지 못했다. 사용자 시각 승인·실제 Android 실행·실기기/Google 성공을 뜻하지 않는다. 단순한 지퍼 상의/하네스 형태의 세련미와 이후 원화 제작은 별도다.
- [Aseprite 레이어/Cel 명세](https://github.com/aseprite/aseprite/blob/main/docs/ase-file-specs.md)를 참고했지만 실제 Aseprite나 생성 모델을 사용하지 않았다.
