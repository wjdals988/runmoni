# Avatar 0.4.0 — 승인 원화의 부위별 착장과 관절 애니메이션

2026-10-25 소스 통합·호스트 검증 완료. 사용자가 승인한 `../v0.3.0/running-motion-art-source.png`를 품질 기준으로 사용한다. 앱 0.1.5-dev/code6의 새 PNG 경로로 연결했으며 서명 APK 빌드 결과는 별도 릴리스 검증에 기록한다.

## 구현 기준

- 공통 얼굴·목·신체에 헤어·상의·하의·양말·신발과 장비를 독립 결합한다. 성별 저장 필드를 추가하거나 브라탑·바이커쇼츠를 성별로 잠그지 않는다.
- 오른쪽으로 달리는 3/4 측면. 256×384 캔버스, 8프레임×90ms=720ms. 양팔과 양다리는 반대 위상이며 왼팔도 고정 이미지가 아닌 독립 관절이다.
- 특수 세트 5종은 산타·스포츠 원피스 수영복·스포츠 비키니·곰인형·독자적인 골든 마스코트. 얼굴과 신체 비율을 교체하지 않고 같은 러너가 옷을 갈아입는다.
- 신체와 주요 의복은 실제 PNG 원화 부품을 사용한다. 캐릭터 원화는 built-in image_gen으로 제작하고, 격자 추출·알파 경계 자르기·최근접 크기 정규화는 `scripts/avatar/pack-art-parts.cjs`로 재현한다. 실제 Aseprite 파일이나 Aseprite 제작물로 표시하지 않는다.
- 기존 13개 내부 슬롯·58개 아이템 ID와 보유품·저장·지갑 규칙을 보존한다. 모자와 액세서리는 부위 점유 규칙을 따르며 여러 부위 동시 착용을 유지한다.

## 검증 경계

사용자가 AVD 검증 제외를 지시했다. 에뮬레이터를 시작하지 않으며, 데스크톱 GIF를 실제 Android 앱 캡처로 표시하지 않는다. 원화 생성·기계적 추출·소스 연결·오프라인 빌드·서명 APK·실기기 확인을 각각 구분해 결과를 추가한다. 공개 업데이트 피드는 게시하지 않은 개발본으로 바꾸지 않는다.

## 실제 결과

- built-in image_gen 15회 요청을 모두 순차 실행했다. 원본 15개와 제작 지시 `prompts.txt`를 보존한다. 첫 팔다리·헤어 원화 2개는 보정본으로 교체했으며, 특수 3세트에는 별도 천 질감 소매·바지·관절 PNG를 추가했다. 단순히 피부를 빨강·갈색·노랑으로 바른 결과를 최종 세트로 사용하지 않는다.
- 앱의 `avatars/v0.4.0/`에는 PNG **63개·752,541bytes**와 manifest를 번들한다. 부품 피벗·길이·원본 격자 경계는 `parts-layout.json`, 해시와 실제 추출 영역은 `packing-verification.json`에 기록한다. 정적 검사 7종은 `static-verification.json`이다.
- `MiniMi.kt`와 지도 마커가 같은 `AvatarSpriteRenderer`/`AvatarArtRepository`를 사용한다. 모양 비율은 256:384이며 지도는 42×63 표시와 84×126 캐시 이미지를 사용한다. 최종 프레임 캐시는 최대24장, 원화/색상 변형 캐시는 각각16/8MiB로 제한한다. 생명주기와 시스템 애니메이션 정지 처리는 유지했다.
- 기존 Java 래스터 소스는 회귀 이력과 이전 테스트를 위해 남지만 새 앱의 Compose/지도 렌더 경로에서 호출하지 않는다. PNG 누락을 옛 도형으로 대체하지 않는다. 범위 밖 저장 정수는 렌더 입력만 기존처럼 floorMod로 정규화하고 보유품·포인트·저장값은 변경하지 않는다.

## 호스트 결과와 재현

`scripts/avatar/export-parts-preview.ps1`은 앱의 Kotlin 저장소·렌더러·카탈로그를 그대로 컴파일한다. 현재 AvatarStyle 선언을 추출하며 Android Bitmap/Canvas/assets와 JSON은 로컬 Java2D 어댑터를 제공한다. 새 패키지를 설치하거나 Gradle/AVD/네트워크를 실행하지 않는다.

`host-preview/run-status.json`이 `passed`인 실행에서 다음을 확인했다.

| 검사 | 결과 |
|---|---|
| 기본 남녀 + 특수5종 | 7클립 × 8개 서로 다른 프레임 = 56 PNG |
| 양팔 손목 | 각각8개 좌표, 각각 가로 이동폭50px 이상 |
| 뼈 길이 | 상완40·하완34·허벅지50·종아리57px,64건 |
| 루프 연결 | 양손목·발목4건의7→0 이동량이 다른 인접구간 최대값 이하 |
| 목→가슴 불투명 연결 | 56/56 |
| 분리 조각 | 8방향·alpha≥16,24px초과 조각0개; 실제 최대 분리면적0 |
| 캔버스 경계 | 56프레임 모두 접촉0px |
| 슬롯 | 58레시피 출력,13슬롯의 variant1 픽셀 변화 |
| 손상 정수 | 음수/최소·최대정수/10000의52건 정상화 |
| 얼굴 | 헤어4×세트6=24조합에서 핵심468픽셀 유지 |

얼굴 검사는 `[151,149,185,165]` 영역의 원본 head_0 alpha≥253 픽셀을 비교한다. 원본 alpha254가 다른 배경과 합성될 때의 작은 RGB 차이는 채널당3까지 허용한다. 투명 외곽·머리로 자연스럽게 가려지는 전체 얼굴 윤곽이나 다른 표정까지 동일하다는 주장이 아니다. 목 연결 검사는 불투명 성분 연결이며 미적 품질을 증명하지 않는다. 호스트 회전 경계와 실제 Android 출력은 다를 수 있다.

초기 실패도 수정 이력으로 남긴다: 앞머리/후드의 얼굴 가림, 산타 모자·신발에 이웃 셀이 섞인 조각, 천 원화의 관절 패치가 치우쳐 골든2번 프레임 종아리가 떨어진 문제를 찾았다. 조각 허용치를 늘리지 않고 추출 영역과 레이어·피벗·관절 겹침을 수정해 재검사했다. 둥근 관절 캡은 원화 끝을 잘라 연결하고 보강 패치는 아래에 둔다.

- `running-pair.gif` / `.png`: 남녀 예시를 함께 재생한다. **8×90ms,420,922bytes**.
- `special-sets.gif` / `.png`: 위 행 일반·산타·수영복, 아래 행 비키니·곰·골든. **8×90ms,1,279,246bytes**.
- 두 GIF는 현재 passed 호스트 소스·원화 해시를 먼저 확인한 뒤 프레임을 기계적으로 배치한 것이다. 캐릭터를 다시 그리거나 프레임을 보간하지 않았다. `scripts/avatar/export-parts-review.cjs`, `review-verification.json`으로 재현한다.
- `host-preview/`에는 PNG116개·개별 GIF7개·프레임/58종 시트와 JSON 진단을 둔다. 생성된 전체 미리보기는 로컬 검증 산출물이며 `host-preview/.gitignore`로 제외하고, 선택한 두 GIF/PNG와 해시·검사 결과만 버전 관리한다.

실제 Android 캡처·Compose 재생·실기기 조작은 이번 검사에 포함하지 않았다. 이전 0.1.3/0.1.4 APK·UI38개 성공을 이 원화의 실행 결과로 합산하지 않는다. AVD 제외는 사용자 지시다.
