# 승인 원본 위의 양말 고정 마스크

루트 후속 검토: 최종 마스크 `dd1dbf5f762e9d219d347d5879a2eeedac7de4397275dbd19645eda8fe4b64a5`를 컴파일했고, 순수 재질208사례와 Android 신규 의상4개 검사를 통과했다. 첫 두 후보의 수치 통과·시각 거절은 [검토 기록](../../../app-review/2026-11-10-widget-wardrobe/README.md)에 보존했다. 최종 crew/knee 호스트 정지 출력에서 추가 차단 이슈를 찾지 못했지만 사용자 시각 승인은 대기 중이다. 아래는 데이터 설계 당시 설명이며 실제 Main 화면·배포는 같은 검토 기록의 완료 근거를 따른다.

이 자료는 남녀 각각8프레임의 기존 보이는 다리 위에 크루 양말·니삭스 재질을 얹는 후보 데이터다. 원본 얼굴·체형·다리 위치를 새로 만들지 않는다. 원본 SHA256은 `f9035f29ced0c7ba513dfe24cb727410a7204dc482fc457e806c7a9b3cdbfa65`이며 원본과 기존 running-kit/wardrobe 마스크는 수정하지 않는다. **사용자 시각 승인은 대기 중**이다.

`annotations.json`의 무릎→발목 축은 고정 원본에 수동으로 제안한 영역 주석이며 실제 해부학적 관절 측정·리그 좌표가 아니다. 남자는 기존 wardrobe의 보이는 피부 leg4에만 적용한다. 여자는 기존 타이츠 fabric2에 적용하고, 종아리 폭의 잘림을 줄이도록 radius24를 사용한다. 같은 축의 crew projection .55~1.0, knee .12~1.0 길이 조건은 유지한다. 특히 접힌1/2/5/6프레임의 앞다리 허벅지·신발 가림은 출력 후 별도 시각 검토가 필요하다.

첫 후보는 여자 radius12와 fabric2만 사용해 종아리 흰 패치·발목 피부 간격으로 보이는 문제가 있었다. 그 첫 수치 검사 통과를 시각 승인으로 해석하지 않는다. 후속 후보는 이미 보이는 여자 발목만 별도 `ankle-coverage.png`에 고정한다. 프레임별 명시 ROI와 원본 alpha≥200·13<hue≤55·S≥.16·V≥.18을 교차하고8방향 연결40픽셀 이상 성분만 선택한다. 작은 frame5의11픽셀 성분은 남긴다. 이 분류는 **데이터 컴파일 때만** 수행하며 앱에서는 피부/색상 추정을 하지 않는다. 새 피부·숨어 있는 정강이·추가 alpha를 생성하지 않는다.

독립 `shoe-protection.png`는 원본 하체 y≥250의 신발 fabric3, coral/red hue, 낮은 채도의 흰 밑창/장식과 어두운 윤곽을 잠근다. 양말 마스크와 이 보호 영역의 교집합은0이어야 한다. 이 보수적인 고정 보호가 모든 의미상 신발 픽셀을 완벽히 인식한다는 주장은 하지 않는다. 새 후보를 실제 출력에서 보고 잔여 패치·가림·연속성을 다시 판단해야 한다.

`scripts/avatar/build-sock-masks.py`를 루트 에이전트가 순차 실행하면 새 namespace에 세 PNG·manifest·검토 수치를 작성한다. source/fabric/wardrobe와 앱 사본의 SHA를 먼저 확인한다. `sock-mask.png`는 R=crew1/knee2 flags, G=명암, B=crew1/knee2 cuff flags와 rib4, A255만 유효하다. A0은 입력을 보존한다. 발목 고정 라벨은 두 길이에 모두 flags3으로 포함한다. 보호/발목 파일은 white 또는0의 이진 데이터다.

원본에서 독립적으로 읽은17개 픽셀을 annotations와 로더에 고정했다. 발목 양성·신발/밑창 음성·작은 frame5 성분 음성의 원본 RGBA와 새 라벨을 교차 검증한다. Android 로더는 원본의 alpha252/253 premultiply 반올림을 데이터 변경으로 오인하지 않도록 검증용 원본을 `inPremultiplied=false`로 읽는다. 실제 렌더러의 원본 표시 경로를 바꾸지는 않는다.

컴파일·호스트 렌더 검사·실제 Android 실행과 사용자 시각 승인은 서로 다른 단계다. 이 문서를 작성한 에이전트는 후속 컴파일/새 PNG 생성·검사를 실행하지 않았다. 실제 Aseprite나 생성 모델 제작물이 아니며 기존 프레임/레이어 분리 개념만 참고했다. `socks:0`은 원래 발목 양말 그대로이고, `socks:3`의 무양말용 피부 underlay는 준비하지 않았다.
