# 런모니 전 화면 디자인 검토

0.13.0-dev의 Android 캡처와 실제 Compose 소스를 출발점으로 삼았다. 일반 전화기에서 출발, 기록 중 조작, 저장한 기록과 공유, 옷장과 크루를 이용하는 순서로 봤다. 라이트·다크는 각각 확인하고 큰 글씨와 좁은 창은 핵심 조작의 회귀 검사에 쓴다. 대시보드는 Android 배포 페이지의 설치와 검증 흐름을 직접 검토한다. [비교 기준 화면](../2026-11-29-outdoor-and-review/README.md)

## 화면별 변경

| 이전 | 반영 | 이유 |
| --- | --- | --- |
| 홈에서 이전 날씨의 다시 확인이 기록 목록 뒤에 있었다. `HomeConditions.kt:155` | 미니미 옆에 확인한 기온과 갱신 상태를 표시하고, 그 자리에서 날씨를 다시 확인한다. | 출발 조건과 러닝 준비를 가까이 둔다. |
| 야외 집중에도 헤더와 하단 탭을 그렸고, 일반 탭에 들어갈 때마다 페이지가 다시 등장했다. `RunmoniApp.kt:222,515` | 열어 둔 러닝의 집중 화면에서 수치와 하단 조작에 공간을 쓰고, 일반 탭은 즉시 전환한다. | 반복 조작에 지연을 더하지 않고 움직이는 중에도 남은 시간을 읽을 수 있다. |
| 지도에서 구간으로 돌아갈 때 이전 화면의 픽셀 위치를 썼다. `RunRecordScreen.kt:284` | 같은 화면 크기에서는 읽던 위치, 글씨나 폭을 바꿨을 때는 선택한 구간으로 돌아간다. | 선택의 의미를 읽기 위치보다 우선한다. |
| 공유 이미지를 만들지 못한 자리에도 대기 표시가 남았고 새 초안 설명이 이전 이미지에 붙을 수 있었다. `RunShareScreen.kt:323` | 현재 미리보기와 설명을 함께 유지한다. 사진·그리기·공유·갤러리 저장 상태와 복구 동작을 해당 위치에 보여 준다. | 결과와 실제 파일의 관계를 분명하게 한다. |
| 탐색에서 러너 숨기기와 지도 재시도가 제스처 지도 아래에 있었다. `RunnerDiscoveryScreen.kt:164` | 러너 숨기기는 지도 위에서, 실패한 지도 재시도는 실패 안내 옆에서 할 수 있다. | 지도 제스처에 가리지 않는 자리에서 제어와 복구를 찾는다. |
| 크루 탈퇴가 즉시 상세를 닫았고 채팅의 이전 전송이 다른 오류에 의해 초안으로 복구될 수 있었다. `CommunityRooms.kt:274` · `RunmoniChat.kt:162` | 탈퇴 확인과 멤버십 갱신을 구별한다. 채팅의 서버 응답과 작성 중인 초안, 실패한 문장을 일치시킨다. | 되돌아가기와 재시도에서 입력과 상태를 보존한다. |
| 첫 실행의 로그인 응답 문구가 게스트 버튼을 밀었고, 프로필 이름의 오류가 입력 아래에 흩어져 있었다. `AppEntryScreen.kt:58` · `UnifiedProfileDialog.kt:87` | 로그인·게스트 선택의 위치를 고정하고, 프로필 확인 상태를 이름 필드 가까이에 둔다. | 진행 중에도 가능한 행동을 찾고 올바른 입력만 다시 확인한다. |
| 옷장의 색상 발음이 겹치고 작아진 창에서 색상표·다시 시도를 지나칠 수 있었다. `RunningKitColorControls.kt:78` · `AvatarClosetScreen.kt:298` | 부위와 색 이름을 함께 읽고, 준비 상태에 맞는 조작과 선택 중인 품목에 돌아간다. | 목록과 피팅을 왕복할 때 대상을 다시 찾는 일을 줄인다. |
| 설정은 고정 여백을 따로 계산하고, 업데이트·자동 백업의 비동기 상태를 일반 문구로 표시했다. `RunmoniDialogs.kt:76` · `AppInformation.kt:132` | 설정도 실제 창 폭의 공통 여백을 쓰고, 상태 변화와 오류를 읽기 안내에 연결한다. | 내 기록·계정·업데이트를 같은 기준선에서 확인한다. |
| 최소 위젯의 한 동작이 포커스 두 개에 있고, 종료 확인 값에 읽기 항목명이 빠졌다. `RunWidgetViews.kt:145` | 위젯 크기별 주요 동작의 이름과 포커스를 정리하고 시간·거리를 문구로 구분한다. | 화면을 보거나 읽기 기능을 써서 조작 대상을 확인한다. |

탐색의 위치 동의와 지도 출처, 파티의 일시·장소·정원·참가, 결과의 원본 수치와 구간표, 옷장의 승인 미니미 아트 및 앱 색상 역할도 함께 대조했다. 파티 상세의 기존 정보 순서와 이미 작동하던 네이티브 조작을 사용한다.

## 다운로드 대시보드

설치 버튼을 짧은 앱 소개 다음에 두고, 대표 캡처 한 장과 추가 화면을 구별한다. 본문 건너뛰기는 키보드 포커스를 실제 본문으로 옮긴다. 설치 상세의 포커스, 해시를 복사하는 중과 성공·실패 안내, 날짜와 릴리스 링크에 접근하는 이름을 정리했다. 기존 정보와 버전·크기·서명 해시를 사용한다.

Hallmark 정적 검사는 다운로드 페이지, 공통 CSS, 레이아웃, 복사 버튼의 네 파일에서 Floor와 Reflex 지적을 모두 해소했다. `accent-ink`를 페이지 배경과 비교한 경고는 실제 버튼 대비 라이트 6.16:1·다크 8.11:1을 확인하고 기록했다.
