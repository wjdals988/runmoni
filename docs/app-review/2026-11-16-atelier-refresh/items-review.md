# 추가 러닝 의류 — 구현 후보 / 2026-11-16

이 문서는 코드 작성·원본/기존 마스크 조사 기록이다. 새 JVM·Android·호스트 출력·작은 크기 시각 검토는 아직 실행하지 않았다. 선택 가능 코드는 개발 후보이며 사용자 원화 승인을 뜻하지 않는다.

새 준비 상태의 정적 예상치는 남자 48 / 여자 46개다(기존 45/43 + 공통 3종). 실제 검사 결과가 아니며 호스트·Android 출력 검토 후 확정한다.

## 검토 후 제외한 후보

- 기존 `top:4` 브라탑 / `top:5` 크롭티: 원본 상의에 가려진 복부·어깨의 승인된 피부가 없다. 옷을 짧게 칠하는 것만으로는 성별별 원형을 보존하는 품목이 되지 않는다.
- 기존 `socks:3` 양말 없음: 원래 신발 주변의 피부 underlay가 없어 기존 ID를 다른 양말로 바꾸지 않았다.
- 헤어·비니: 머리 외곽·앞머리 가림은 별도 검증이 필요하다. 이번 Root의 실제 Aseprite 세트 머리 재질 작업과 소유 영역이 겹치므로 추가하지 않았다.
- 미승인 수영복 `costume:2/3`: 준비 상태를 올리지 않았고 새 피부나 신체를 생성하지 않는다.

## 구현 / 경계

- `AvatarAtelierClothing.kt`: 순수 정수 픽셀층. 원본·입력 마스크를 쓰지 않고 복사 결과를 돌려준다. 기존 명암 팔레트/명시 라벨 외의 런타임 피부 추정·전역 색상 필터가 없다.
- `ApprovedAvatarRenderer.kt`: 새 품목에만 기존 짧은 소매/크루/블루 러닝화 기반 형상을 먼저 적용한 뒤 새 재질층을 덧댄다. 기본 캐시 조기 반환·기존 품목 코드는 유지하며 새 버전을 캐시 키에 포함한다. 장비는 이후 적용하므로 소매·조끼·손목 가림 순서가 유지된다.
- 메시 저지는 기존 원화 천 라벨이 전경 손 밑으로 계속되는 일부 셀을 독립 `hand-protection.png`로 복원한다. 읽기 전용 마스크 조사에서는 남자 F2에 124px, 여자 F1/F2/F5에 1/4/8px의 천/짧은 소매와 손 겹침을 확인했다. 이것은 픽셀 라벨 교집합 측정이며 새 렌더 결과나 시각 승인이 아니다.
- 신발의 ROI는 원본 `fabric3` 연결 영역의 범위를 읽어 각 셀에 수기로 주석했다. 숨은 남자 F5 뒤 신발은 보이는 81px 조각 범위만 다룬다. 실제 출력에서 좌우 패널 연결과 회전된 뒤 신발의 방향을 확인해야 한다.

## 통합 발견 / Root 후속 소유

`RunnerPresenceRepository.decodeAvatar`가 모든 슬롯을 0..5로 제한하고 Firestore의 공개 위치 avatar 규칙도 `top<=5/socks<=3/shoes<=3`이다. 새 항목 공유를 위해 슬롯별 유효성 및 상한 6/4/4 동기화가 필요하다고 Root에 전달했다. 해당 파일은 이 담당자가 수정하지 않았다. 새 Rules 게시와 실제 운영 쓰기는 별도 확인 사항이다.

Root가 소유 범위를 추가 승인한 legacy HTTP `backend/main.py`·`models.py`는 새3개 품목과 입력 상한을 동기화했다. 기존62개 응답 순서/ID는 그대로 두고 새3개를 뒤에 붙여65개다(Android61 + 기존 legacy accessory alias4). 팔레트 상한은0..5 그대로다. 기존 두 카탈로그 검사 스냅샷을 갱신하고 무료 claim/재claim·미보유 거절·777P/성별/색/구보유·옛 클라이언트 PATCH·범위 밖 거절 회귀를 추가했다. 서버 실행·배포·새 테스트 성공을 주장하지 않는다.
