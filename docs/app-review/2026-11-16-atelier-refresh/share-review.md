# 공유 편집 전면 개편 설계·자가비평

frontend-design을 명시적으로 적용한다. 런모니의 기억점은 사용자가 고른 실제 사진, 승인 미니미와 자기 러닝 기록이다. 사진을 위아래 테마 띠로 자르는 구조를 제거한다. 구현 전 검토 기록이며 빌드·Android·사진 선택/저장/SNS 실행 결과가 아니다.

## 토큰과 구성

- 사진: 기존 cover crop/최소1·최대3배·이동 경계를 유지하고 전체 캔버스를 채운다. 불투명 header/footer, 전체 tint, gradient는 사용하지 않는다.
- 사진 없음: 글씨 밝기에 맞춘 중립 charcoal `#20272B` 또는 밝은 회색 `#F4F6F7` 한 색이다. 앱 UI에서는 `사진 추가`가 첫 명확한 동작이며 기록만 저장/공유하는 기존 경로도 유지한다.
- 글씨: 밝은 `#FFFFFF`/어두운 `#17232A` 두 선택, 반대색의 얇은 stroke와 작은 shadow로 글자 둘레만 분리한다. 본문을 덮는 색면을 만들지 않는다. Android 시스템 sans와 실제 기록값을 사용한다.
- 스타일3종: 클린은 거리와 짧은 기록 줄, 기록 강조는 큰 거리와 구분된 시간/페이스, 스탬프는 폭이 좁고 중앙 정렬된 작은 기념 기록이다. 브랜드·날짜·닉네임·문구는 같은 이동 블록에 붙인다. 장식 번호/허위 달성 배지/색 그라데이션은 없다.
- 편집 UI: 미리보기→사진/기록/미니미3도구→선택 속성→저장/공유다. 고정 Back, 큰 글씨/짧은 IME 창의 단일 scroll/footer fallback, 최소48dp를 유지한다. 구역24dp·내부16dp로 읽기 순서를 만든다.
- 1:1이 기본이며4:5·9:16도 유지한다. 사진·기록·미니미는 선택 도구에 따라 각각 drag한다. 기록과 미니미는 독립 좌표, 양쪽 모두 방향 버튼·빠른 위치를 제공한다. 미니미는 기존 크기/pinch를 유지한다.

## 자가비평과 결정

큰 수치+동일 카드들을 늘리는 대시보드 구성을 버리고 실제 사진을 하나의 작업영역으로 삼았다. 새 스타일도 색상 테마4개의 이름만 바꾸지 않고 실제 조판과 폭/정렬을 바꾼다. 스탬프에 모조 우표 테두리나 강한 배지를 넣는 것은 사진보다 장식이 앞서는 상투성이 있어 빼기로 했다. 그림자/외곽선은 글자 주변에만 적용한다.

고정 통계 띠를 없애므로 미니미를 강제로 그 띠 밖으로 튕기는 예전 제약도 제거한다. 기본 배치는 기록과 겹치지 않게 하고 자유 배치에서는 사용자가 만든 겹침을 허용한다. 기록을 앞에 그려 수치가 완전히 가려지지 않게 한다. 미니미 자체의 실제 투명 bounds·aspect·최근접 픽셀과 캔버스 안 fitting은 보존한다. 이전 고정 띠 기반 테스트는 새 자유 배치·실제 원본 보존 계약에 맞춰 바꾼다.

기존 theme/placement enum 이름과 순서는 구형 저장 draft를 위해 유지한다. 새로운 스타일/글씨톤/기록 좌표는 draft 끝에 추가하고 기존13필드 Saver도 복원한다. 미리보기와 내보내기는 계속 동일 renderer bitmap이며 실제 기록의 재확인/nonce·auth·편집 revision·late callback·취소·URI/EXIF/GPS 비공개 경계를 건드리지 않는다. AppViewModel/AppActions API는 바꾸지 않는다.

## 필요한 검증

모든 비율·3스타일·밝고 어두운 글씨와 사진에서 사진 가장자리가 원본 crop 색으로 남아 띠/tint가 없는지, 글자 픽셀이 실제로 그려지고 PNG round-trip이 같은지 검사한다. 승인 남녀 bitmap은 빌려 쓰고 원본 배열/색/비율을 보존한다. 기록·미니미의 독립 이동/큰 글씨/320dp·IME/버튼 대안/Saver 복원을 확인한다. 원래 MediaStore·stale export·dispose/authorize 테스트는 유지한다. Root가 실제 실행하기 전에는 통과로 기록하지 않는다.

## 구현 후 소스 자가검토·남은 확인

3개 제품 파일과 관련 share 테스트만 수정했다. `RunShareCardRenderer`의 LinearGradient/Shader·불투명 panel draw를 삭제하고 photo cover·원본 도트·로컬 글자 stroke/shadow만 남겼다. 기존 theme enum과 ordinal은 유지하지만 새 renderer의 사진 tint나 fallback 색을 선택하지 않는다. 사진이 없을 때는 글씨톤에 맞춘 중립 단색을 사용한다.

UI는 사진/기록/미니미3도구다. 기록 도구의 style/tone/위중아래 위치/방향 버튼과 preview drag는 새 draft의 recordX/Y로 연결한다. 미니미와 사진 좌표는 별개다. 구형13필드와 새17필드 Saver 복원을 준비했고, 기존 auth·record 재확인·editRevision·lifecycle·cancel·동일 bitmap 저장 경로는 유지했다.

검사 선언 수는 domain JVM10, Android renderer6/UI5/controller1/IME2다. 이는 파일에서 읽은 메서드 수이며 실행/통과 수가 아니다. 기존 UI/controller 테스트의 폐기된 theme 제어를 실제 새 ratio/style/tone/위치 제어로 바꾸고, stale callback/중복 저장/권한 철회와48dp/전체 bounds 검사 기준은 낮추지 않았다.

현재 빌드·테스트·Android 캡처·실제 사진 선택/저장/SNS·Git은 실행하지 않았다. Root가 글씨의 실제 크기/외곽선·밝고 어두운 사진·각 preset과 세 비율을 직접 확인해야 한다. 사용자가 기록과 미니미를 겹친 경우 기록이 앞에 그려지는 자유 배치 계약을 안내한다. 새 스타일이 원래 사진의 피사체를 가리는지와320dp/font2·IME 안에서 긴 속성 영역을 다루기 편한지도 실제 후속 검토 대상으로 남긴다.
