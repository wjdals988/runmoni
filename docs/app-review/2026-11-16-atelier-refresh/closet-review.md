# 옷장 작업영역 정리 — 2026-11-16

상태: 구현·소스 검토 완료. 이 문서는 새 빌드, Android 실행, 시각 승인 또는 게시 성공의 증거가 아니다.

## 설계와 자가비평

`work/frontend-design/SKILL.md`를 적용했다. 기존 Chalk `#F7F9FA`, Paper `#FFFFFF`, Ink `#24343D`, Muted `#5B6D73`, Ocean `#356F78`, Mist `#E7EFF1`과 한국어 시스템 Sans를 유지한다. 현재 미니미를 가장 큰 작업영역으로 두고, 아래에는 실제 의복·장비 부분 그림과 이름·선택 체크만 정렬한다. 색상이나 가격 배지를 카드마다 반복하지 않는다.

첫 제안은 그림 없는 단일 목록이었다. Root 비평대로 선택 전 외형 비교가 사라지는 후퇴가 있어 폐기했다. 최종안은 승인 렌더의 정지 frame0에서 실제 부위만 잘라 64dp에 보여준다. 세트는 작은 전신이다. 부분 그림을 상품용 새 원화로 만들거나 가림을 지운 독립 상품 이미지로 가장하지 않는다.

```text
옷장                                      재생 / 닫기
현재 미니미                         현재 착용 / 남자·여자
헤어  모자  얼굴  상의  하의  세트  양말  신발  액세서리

작은 실제 상의 부분 그림   아이템 이름                체크
작은 실제 상의 부분 그림   아이템 이름
선택한 의복의 색상
```

## 반영

- 큰 전신 두 열 비교를 없애 한 열로 통일했다. 기본 행은 80dp 이상이며 고정 높이로 텍스트를 자르지 않는다. 텍스트·선택 상태·실제 부분 그림의 읽기 순서를 유지한다.
- 얼굴·머리·모자, 상의, 하의, 양말·신발, 장비의 실제 합성 frame0 영역을 Canvas에서 그린다. 원본 PNG·레이어·몸 비율·팔/다리·애니메이션을 변경하지 않는다. 합성 캐시의 기존 bitmap을 재사용하며 별도 부분 bitmap을 만들지 않는다.
- 소스 자가검토에서 모자 챙이 x246까지 닿는 것을 확인해 머리 부분 crop의 가로폭은 frame 전체256px로 보존했다. 실제 새 캡처의 시각 확인은 아직 하지 않았다.
- 주 미니미의 실제 첫 프레임 이후 보조 그림을 준비하는 gate를 보존했다. 썸네일 요청 전체를 avatar/slot/ready/retry 키에 묶어 이전 착용 그림을 새 요청 이름 아래 재사용하지 않는다. 실패 시 48dp 명시적 재시도를 제공한다.
- 성별 선택의 선택색을 Mist로 분명히 했다. 남녀 콜백·RadioButton 선택 상태·48dp 최소 조작 영역·재생/닫기는 유지한다.
- `avatarItemDisplayName`은 표시만 담당한다. 같은0번 ID의 남자 쇼트/싱글렛/쇼츠와 여자 포니테일/반팔/타이츠를 구분하고 신발은 기본 러닝화로 읽힌다. 의복 색상은 독립 변경되므로 이름에 원본의 고정 색상을 붙이지 않는다. 카탈로그 원래 이름/ID·가격·비0번 이름을 수정하지 않았다.
- 좁은 큰 글씨(아이템 영역 360dp 미만)는 기존처럼 부분 그림을 생략하고 이름 폭을 보존한다. 주 미니미는 그대로이며 단일 스크롤, 가로 작업영역, 짧은 창 전체 스크롤, safeDrawing∪IME 단일 소유도 유지한다.
- 미준비 선택 보관, 세트 가림/선택 시 해제, 의복 색상 영역, 무료 획득/저장 콜백, 기존 ID·9탭·13슬롯·기존 보유권/포인트를 바꾸지 않는다. 카탈로그 목록/준비 여부는 계속 실제 모델에서 읽는다.

## 태그와 검토

`closet_avatar_preview`, `closet_safe_content`, `closet_item_list`, `closet_content_end`, `closet_close`, `closet_animation`, 모든 슬롯/아이템/성별/상태 태그를 유지한다. `closet_preview_{slot}_{variant}`는 같은 후보의 실제 부분 이미지다. `closet_compare_list`는 유지하고 폐기된 두 열의 `closet_compare_grid`는 더 이상 표시하지 않는다. 품목별 비교 이미지 태그를 빈 박스나 텍스트에 재사용하지 않았다.

관련 `RunningKitColorsUiTest`의 신발 색상 픽셀 검사는 전신 바닥 대신 실제 신발 crop의 아래 절반을 확인하도록 수정했다. 다른 신발의 기본색, 같은 신발 재선택 시 맞춤색 유지, 다른 의복 영역/포인트/보유권 보존이라는 검사의 목적은 같다. 실제 실행은 Root의 순차 검증에 남겼다.

정적 스크립트로 남녀/crop 조합18개의 좌표가 256×384 frame 안에 있는지, 핵심 태그·선택/가림/취소 경로와 공백 형식을 확인했다. 소스를 읽어 고정 행 높이·이름 축약·새 이미지/의존성/도메인 변경이 없는지도 확인했다. 이 범위에서 Kotlin 빌드·Android 테스트·AVD·ADB·네트워크·Git 명령은 실행하지 않았다.

독립 `benchmark_design_review`의 읽기 전용 검토에서도 현재 소스상 P0/P1·명백한 UX 후퇴는 발견하지 못했다. 실제 부위의 범위, 중첩 재시도 동작, 작은 창/큰 글씨 검증이 필요하다는 한계는 그대로다. 현재 관련 Android 테스트에는 기본 아이템 표시 이름을 고정한 문자열 단언이 없으며, 선택/상태 태그와 보관 안내 원문은 바꾸지 않았다.

## 미확인과 엄격한 후속 확인

- 새 Android 캡처에서 남녀 모든 부위의 crop이 장비를 충분히 보여주는지 확인해야 한다. 다른 장비/의복의 실제 가림은 crop에도 남는다. 신발은 frame0의 앞 신발을 보여주며 양쪽 신발·전 프레임을 비교한 것은 아니다.
- 실제320dp/font2, 짧은 가로 창, IME 열린 창에서 마지막 품목·색상·성별·닫기의 전체 bounds와 텍스트 넘침을 확인해야 한다. 기존 큰 글씨 분기의 소스 보존은 새 실행 통과를 뜻하지 않는다.
- 빠른 연속 아이템/성별 변경, 주 미니미 로딩/실패·재시도, 썸네일 실패·재시도, 세트 해제와 장비 동시 착용을 실제로 확인해야 한다.
- 원본 품질/새 Aseprite 의복의 완성·실제 저장/계정 백업·휴대폰/Google·사용자 시각 승인·같은 키 공개 APK는 이 UI 작업에서 검증하지 않았다.
