# 상호 소스 검토

프로필 담당과 Rules/지역명 담당이 소스를 나누어 확인하고 Root가 통합했다. 이 문서는 실행 검사를 대신하지 않는다.

- 보류 Auth 후보와 서버 profile 확인을 분리하고 재시도에 같은 UID를 유지한다. 과거 anonymous Auth만 남은 경우도 원래 계정을 버리지 않는다. public UID·위치 공유·Google 연결은 서버 profile 확인을 거친다.
- 연결 ACK와 방 목록 조회 실패를 분리한다. 이전 snapshot이 저장 직후 이름을 되돌리지 않도록 작업 세대와 저장 receipt를 경계로 삼는다.
- 연결뿐 아니라 저장에도 편집창을 열 때의 UID/backend를 전달한다. UID가 둘 다 빈 값이어도 Firebase→HTTP 변경 후 오래된 입력이 다른 대상으로 저장되는 일을 막는다. 기존2인자 호출과 테스트 delegate의 호환 경로를 유지한다.
- 지역명은 기존 약1km격자의 행정필드만 받는다. 세부주소·새 공유를 추가하지 않고, 현재 위치와 예보 격자를 결합한다. 취소/메모리 cache/시간 제한·legacy worker/queue 상한과 늦은 결과 무시를 확인했다. native 동기 호출 자체의 중단 성공을 보장하지 않는다.
- 현재 저장소 Rules의 닉네임 예약과 과거 정책의 차이를 확인했다. 운영 규칙이 실제 과거 버전이라고 단정하거나 운영 배포 권한이 있다고 가정하지 않았다.

실제 컴파일/Android에서 발견된 API getter 오류·지도 출처 잘림과 localhost 프록시 실패는 CHANGELOG/원문에 별도 남겼다. 수치 검사와 사용자 시각 승인·운영 성공을 구분한다.
