## 판단

개인 러닝과 초대 지인용 기능 검증은 이어갈 수 있다. 대중 서비스 준비는 끝나지 않았다.
GPS 기록을 네트워크·오디오와 분리하고, SQLite 쓰기를 트랜잭션으로 보호하며,
중복 finalize·구매·정원 경쟁을 테스트한 점은 유지해야 한다.
가장 먼저 해결할 것은 새 화면보다 **계정과 기록의 소유권 및 동기화 복구**다.
다음으로 실기기에서 GPS+음성+음악의 동시 사용을 검증해야 한다.

기준 시점 GitHub 조회에서 열린 이슈/PR 및 Actions 실행 이력은 없었다.
기존 검증 문서는 과거 결과이며 이번 환경에서 다시 실행한 결과와 분리한다.

마일리지 GPS 필터는 악용 완전 방지 수단이 아니며, 여러 기기에서 같은 코스를 다른 ID로 올리는

`markSynced`가 로컬 mileage까지 덮는 현재 모델은 A01 설계에서 분리한다.

## 이번 검증과 한계

- Python 3.12, 백엔드 lock 설치 후 `python -m pytest -q backend/tests`: **40 통과**.
- 별도 venv에 브리지 requirements 설치 후 `python audio-bridge/run_tests.py`: **32 통과**.
- pglast 7.21: **142개 SQL문·20개 함수 본문 구문 검사 통과**.
- Android SDK가 없는 이번 작업 환경에서는 Android 빌드·JVM·instrumentation을 다시 실행하지 않았다.
- pgTAP/RLS 실행, 야외 GPS, NAVER 인증, 실제 LiveKit 2대 송수신, 외부 음악 앱 호환성은 미검증.
- Python 테스트는 TestClient를 사용하는 인프로세스 검증이다. Android→실제 HTTP 경로 재검증과 다르다.
- 백엔드/브리지의 서로 다른 FastAPI·LiveKit 버전은 이번에 일괄 올리지 않았다. 전이 의존성 경고가 남아 있다.

`.github/workflows/ci.yml`에 backend/bridge/SQL 구문/Android unit·lint·APK 빌드를 추가했다.
CI 설정 추가를 CI 통과로 간주하지 않으며, 기기 instrumentation과 실제 RLS는 별도 검증이다.
첫 원격 실행에서 backend/SQL은 통과했고 bridge 종료 경쟁 및 Android setup의 폐기된
`tools` 패키지 요청이 실패했다. bridge 정리와 테스트 동기화를 수정하고,
Android setup 패키지를 `platform-tools`로 명시했다. 최종 원격 결과는 PR checks를 확인한다.
새 기능 순서와 완료 조건은 [로드맵](ROADMAP.md)을 따른다.
