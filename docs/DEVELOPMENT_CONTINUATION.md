## 이번 소스에 구현한 범위

- **크루 → 파티 구조:** 크루를 최상위 탐색으로 두고 해당 크루에서 파티를 생성·조회·참가한다. 크루별 자식 조회, 명시적인 ‘크루 가입하고 참가’, 상세/뒤로 단계와 삭제 동선을 연결했다. 새 독립 파티 생성은 막고 기존 독립 파티 데이터는 파괴하지 않는다.
- **파티 삭제/권한:** 삭제 표식으로 발견·신규 참가·대화를 닫고 개인 참여 링크를 원자적으로 정리한다. 부모 크루를 떠난 주최자/DJ의 대화 접근을 막는다. 선택적 정리의 시간 초과가 성공한 조회/삭제 커밋을 실패로 뒤집지 않도록 분리했다. 실제 운영 적용은 새 규칙 게시 후 검증해야 한다.
- **남녀 기본형:** 명시적인 `AvatarStyle.gender`와 `male`/`female` JSON을 저장한다. 기존 JSON의 필드 누락·알 수 없는 값은 남자 기본형으로 복원하며 헤어로 성별을 추측하지 않는다. 승인 v0.3 원본의 **두 행×8프레임**을 직접 잘라 성별별 캐시와 홈·나·옷장·지도 공통 표시를 사용한다.
- **테스트 전 아이템0P:** 기존9개 분류·13슬롯·58개 아이템 ID를 유지하면서 무료 획득/선택 저장을 허용한다. 기존 포인트·보유 내역을 초기화하거나 차감하지 않는다. HTTP 파일럿도 무료 여부를 확인하며 성별·기존 선택의 저장 호환을 유지한다.
- **원화 준비 경계:** 비기본 아이템을 선택해도 해당 프레임 원화가 없으면 선택만 보관하고 승인 기본형을 표시한다. UI에 이 상태를 명시하며 ‘옷이 실제로 바뀜’이나 전체58종 완성으로 표시하지 않는다. 거절된 v0.4 조립 렌더러는 재활성화하지 않는다.
- **UI/UX:** 크루/파티의 화면 단계, 제목/본문/행간과 정렬, 옷장의 가로 카테고리·아이템 그리드·남녀 선택을 정리했다. 클라우드 Android의 계층/뒤로·큰 글씨/정렬·무료 선택/저장과 실제 MainActivity/HTTP 연결을 범위별로 검증했다. 다른 실기기·TalkBack·사용자 시각 승인은 별도로 남아 있다.

승인 원본은 `docs/design/avatars/v0.3.0/running-motion-art-source.png`, SHA256 `f9035f29ced0c7ba513dfe24cb727410a7204dc482fc457e806c7a9b3cdbfa65`,2048×768/셀256×384다. 파일과 번들 사본을 덮어쓰지 않는다. 성별 전환 구현은 의복 레이어·수영복 승인·여자 양팔 동작 보정 완료와 별개다.

## 완료한 검증·공개의 경계

현재0.3.1의 최종 debug2+1+1 실행과 최초10개 중1개 테스트 오류·native 사진의 버튼 잘림/수정·전체CTA/기준선/정리는 [원시 보고서/사진](app-review/2026-11-03-context-ui/README.md)에 보존한다. 이전0.3의 SDK/demo·Android 검증은 [이전 실행 기록](app-review/2026-11-02-crew-ux/README.md)으로 구분한다. 반복 실행을 고유 개수로 합산하지 않는다.

공개0.3.1의 서명 CI/3자산/HEAD200 검증은 [RELEASE_REVIEW_0.3.1_20261103.md](RELEASE_REVIEW_0.3.1_20261103.md)에 있다. 실제 휴대폰·공개 서명 release 실행·Google·운영 Firebase 쓰기는 미검증이며 설정 ready나 소유자 콘솔 보고로 대신하지 않는다. 후속 피드/문서 커밋은 APK 출처 `3074c0f40797a2452b36e4277dd559f94a31ac07`가 아니다.

## 바로 이어서 완료할 일

1. **R04 새0.3.1 공개 후 동기화:** 이미 공개·검증한 APK의 metadata로 피드/대시보드를 반영하고 main·실제 운영 URL의 버전13/다운로드/크기/해시·사진5장/배포 상태를 확인한다. 결과를 최신 게시 검토에 추가하기 전 완료로 표시하지 않는다. 실제 APK 출처는 `3074c0f40797a2452b36e4277dd559f94a31ac07`이며 과거 출처/바이트를 보존한다.
2. **R03 새 운영 규칙 적용 확인:** 검토한 [firestore.rules](../firebase/firestore.rules)를 소유자가 운영에 게시해야 한다. 기존1~5번 완료 보고를 이번 새 규칙 게시로 재해석하지 않는다. 관리 계정/서비스 계정키를 채팅으로 받거나 공개 읽기만으로 운영 삭제가 검증됐다고 표시하지 않는다. 소유자 응답/운영 권한 확인 전 이 항목을 대기로 유지한다.
3. **F01 실제 휴대폰·Google·운영 쓰기:** [휴대폰 확인 순서](FIREBASE_COMMUNITY.md#휴대폰에서-확인하는-순서)에 따라0.3.1 설치/같은 키 업데이트·기록 보존·Google 계정 선택/온라인 응답/요약 백업, 두 기기의 같은 크루/파티·채팅·정원·삭제 후 접근 차단을 각각 확인한다. 실제 장애가 보고되면 후속 기능보다 먼저 수정한다.
4. **다음 독립 구현 F03:** 공개 동기화 기록을 닫은 뒤 원본 품질의 의복/수영복 레이어·명시 마스크/색상 작업을 이어간다. 새 규칙/휴대폰 결과를 기다리는 동안에도 원화와 오류 주입 검증 등 독립 작업을 진행할 수 있다. F02+U01이나 이미 확인한0.3 빌드/게시를 완료 전 단계로 되돌려 반복하지 않는다.

## 그다음 독립 개발

F02+U01의 기본형/무료 옷장 구현을 다시 시작하지 않는다. **F03 원본 품질의 의복/수영복 레이어**는 프레임별 의복·가림·명시 마스크/명암 팔레트와 사용자 시각 검토가 필요하다. 기존 얼굴·체형/비율/명암을 보존하고 보호 영역 불변·비키니 상/하 독립색·저장·7→0/양팔 동작을 확인한 뒤 준비된 아이템부터 실제 착용에 연결한다. **F04 익명 계정 복구·크루장 권한 이양·신고/차단**은 기존 익명 UID/참여/권한을 보존하는 연결 정책부터 정한다. Google 자격이 이미 다른 계정에 연결된 충돌·실패/취소에도 기존 세션을 잃지 않는지 검증하며 단순 로그아웃/새 UID 전환을 복구로 표시하지 않는다. F05 저장 실패·중단 복구/실기기 GPS 검증은 실행 가능한 오류 주입과 휴대폰 확인을 구분해 진행한다. 상세 완료 조건은 [우선순위](DEVELOPMENT_PRIORITIES.md)에 있다.
