## 이번 소스에 구현한 범위

- **크루 → 파티 구조:** 크루를 최상위 탐색으로 두고 해당 크루에서 파티를 생성·조회·참가한다. 크루별 자식 조회, 명시적인 ‘크루 가입하고 참가’, 상세/뒤로 단계와 삭제 동선을 연결했다. 새 독립 파티 생성은 막고 기존 독립 파티 데이터는 파괴하지 않는다.
- **파티 삭제/권한:** 삭제 표식으로 발견·신규 참가·대화를 닫고 개인 참여 링크를 원자적으로 정리한다. 부모 크루를 떠난 주최자/DJ의 대화 접근을 막는다. 선택적 정리의 시간 초과가 성공한 조회/삭제 커밋을 실패로 뒤집지 않도록 분리했다. 실제 운영 적용은 새 규칙 게시 후 검증해야 한다.
- **남녀 기본형:** 명시적인 `AvatarStyle.gender`와 `male`/`female` JSON을 저장한다. 기존 JSON의 필드 누락·알 수 없는 값은 남자 기본형으로 복원하며 헤어로 성별을 추측하지 않는다. 승인 v0.3 원본의 **두 행×8프레임**을 직접 잘라 성별별 캐시와 홈·나·옷장·지도 공통 표시를 사용한다.
- **테스트 전 아이템0P:** 기존9개 분류·13슬롯·58개 아이템 ID를 유지하면서 무료 획득/선택 저장을 허용한다. 기존 포인트·보유 내역을 초기화하거나 차감하지 않는다. HTTP 파일럿도 무료 여부를 확인하며 성별·기존 선택의 저장 호환을 유지한다.
- **원화 준비 경계:** 비기본 아이템을 선택해도 해당 프레임 원화가 없으면 선택만 보관하고 승인 기본형을 표시한다. UI에 이 상태를 명시하며 ‘옷이 실제로 바뀜’이나 전체58종 완성으로 표시하지 않는다. 거절된 v0.4 조립 렌더러는 재활성화하지 않는다.
- **UI/UX:** 크루/파티의 화면 단계, 제목/본문/행간과 정렬, 옷장의 가로 카테고리·아이템 그리드·남녀 선택을 정리했다. 실제 작은 화면·큰 글씨·뒤로/키보드·저장 동작 검증과 시각 승인은 아직 다음 단계다.

승인 원본은 `docs/design/avatars/v0.3.0/running-motion-art-source.png`, SHA256 `f9035f29ced0c7ba513dfe24cb727410a7204dc482fc457e806c7a9b3cdbfa65`,2048×768/셀256×384다. 파일과 번들 사본을 덮어쓰지 않는다. 성별 전환 구현은 의복 레이어·수영복 승인·여자 양팔 동작 보정 완료와 별개다.

## 바로 이어서 완료할 일

1. **현재 소스로 실제 Android 재검증:** 계층 이동/뒤로·파티 생성/참가/삭제, 남녀16개 원본 셀·성별 캐시/빠른 전환, 무료 선택/포인트·보유권 보존, 기존 JSON/저장/재실행을 확인한다. native320dp/글씨200%·키보드·스크롤·선택 상태와 실제 캡처도 확인한다. 과거 Android 검사를 이번0.3 실행 결과에 합산하지 않는다.
2. **검토 근거와 PR:** 실패/수정/최종 실행을 [현재 검토](CREW_CLOSET_REVIEW_20261102.md)와 [CHANGELOG](../CHANGELOG.md)에 기록하고 커밋·푸시·PR을 진행한다. 테스트 통과와 사용자 시각 승인은 구분한다.
3. **새 운영 규칙 적용 확인:** 검토한 [firestore.rules](../firebase/firestore.rules)를 소유자가 운영에 게시해야 한다. 기존1~5번 완료 보고를 이번 규칙 게시로 재해석하지 않는다. 관리 계정/서비스 계정키를 채팅으로 받거나 공개 읽기만으로 운영 삭제가 검증됐다고 표시하지 않는다.
4. **동일 키의0.3 서명 후보:** 확정된 소스로 CI 빌드/테스트·서명·non-debuggable·패키지/버전/code·내장 출처·크기/해시와 서버3자산을 검증한다. 실제 자산이 게시되기 전에는 공개 피드나 대시보드 다운로드를 올리지 않는다.
5. **공개 후 동기화:** 검증한 APK만 공개 피드/대시보드에 연결하고 운영 URL의 실제 버전·다운로드·해시를 확인한다.0.2.1과 과거 APK의 출처·바이트는 보존한다. 새 규칙 미게시/실기기 미검증은 실제 상태대로 안내한다.
6. **실제 휴대폰·Google·운영 쓰기:** [휴대폰 확인 순서](FIREBASE_COMMUNITY.md#휴대폰에서-확인하는-순서)에 따라 설치/같은 키 업데이트·기록 보존·Google 계정 선택/온라인 응답/요약 백업, 두 기기의 같은 크루/파티·채팅·정원·삭제 후 접근 차단을 각각 확인한다. 실제 장애가 보고되면 후속 기능보다 먼저 수정한다.

## 그다음 독립 개발

F02+U01의 기본형/무료 옷장 구현을 다시 시작하지 않는다. 이번 검증·배포가 끝나면 **F03 원본 품질의 의복/수영복 레이어**를 우선 진행한다. 프레임별 의복·가림·명시 마스크/명암 팔레트와 사용자 시각 검토가 필요하다. **F04 익명 계정 복구·방장 이양·신고/차단**은 실제 인증 동작을 바탕으로 기존 UID/참여/권한을 보존하는 정책부터 정한다. F05 저장 실패·중단 복구/실기기 GPS 검증은 실행 가능한 오류 주입과 휴대폰 확인을 구분해 진행한다. 상세 완료 조건은 [우선순위](DEVELOPMENT_PRIORITIES.md)에 있다.

## 작업 기준

`AGENTS.md` → 이 문서 → `DEVELOPMENT_PRIORITIES.md` → `DESIGN.md` → `CHANGELOG.md`를 읽고 최신 작업 트리/공개 상태를 확인한다. UI는 [DESIGN.md](../DESIGN.md)의 awesome-design-md 참고 기준을 따르고 원화는 Aseprite 레이어/프레임 개념을 참고하되 실제 도구 사용 여부를 정확히 기록한다.

기본 Gradle은 캐시 우선·오프라인·작업자1개다. 설치/빌드/전송/이미지 생성은 겹치지 않는다. AVD는 클라우드 전용 `Runmoni_Cloud_29` 한 개를 headless/TCG로 검증 후 종료하고 사용자 PC AVD·외부 공개 터널/방화벽 예외는 사용하지 않는다. 시스템 팝업이 앱을 가렸다면 실패/한계를 기록하며 가려지지 않은 앱 화면이나 실기기 성공으로 표시하지 않는다. 비밀·설정 원문·개인 GPS를 Git/로그/채팅에 넣지 않는다.

이전 계획·승인/실패·배포 이력은 [CHANGELOG](../CHANGELOG.md), [0.2.1 배포 검토](RELEASE_REVIEW_20261101.md), [현재0.3 검토](CREW_CLOSET_REVIEW_20261102.md)에 보존한다. 과거 CI JSON의 false를 최신 소유자 보고로 덮어쓰지 않는다.
