## 상호 검토와 결정

크루 담당에게 flat row 전환 후에도 전체 행의 `Role.Button`·기존 testTag·최소 조작 영역, 긴 이름/본문 줄바꿈, 생성 진입과 연결 오류/빈 상태 구분을 유지하도록 요청했다. 옷장 담당에게는 미준비 아이템을 착용으로 표시하지 않는 점, `checked` 선택 semantics, 남녀 전환·카테고리 스크롤·큰 글씨 1열과 기존 선택 저장을 우선 조건으로 전달했다.

크루 담당의 초기 diff를 독립적으로 검토했다. `CrewRoomCard`와 `PartySummary`는 전체 행의 버튼 역할·기존 태그·48dp 최소 높이를 유지하며, 파티 참가 중에도 현재 인원/정원을 함께 표시한다. 이름·일정·페이스를 고정 높이에 자르지 않고, 크루 설명만 목록에서 2줄로 요약한다. 상세의 소개에서 원문을 볼 수 있다. 반복된 ‘이 크루의 파티’ 제목을 제거하고 생성 행동을 탭/검색 아래에 남겼다. 권한·조회·오류 조건에는 변경이 없다. 이 소스 검토에서 차단할 회귀는 발견하지 않았으며 실제 큰 글씨의 겹침·행 클릭·뒤로·생성 접근은 Android 확인 대상이다.

옷장 담당의 초기 diff에서는 기본형에만 작은 실제 미니미를 표시하고 미준비 항목에는 가짜 의상 이미지·공통 행거를 넣지 않았다. 모든 항목의 제목을 첫 행에 두고 선택 체크를 함께 표시한다. 반복 가격은 공통0P 안내로 모으고 미준비 선택에는 기본형 표시·선택 보관을 명시했다. 최소112dp는 고정 높이가 아니며 긴 이름·상태의 줄바꿈을 허용한다. 선택 역할·태그·기존 저장 호출·성별/카테고리/세트 가림 조건에 변경은 없다. 이 소스 검토에서 P0 회귀는 발견하지 않았지만 일반2열의 선택 체크와 긴 이름·작은 실제 이미지 옆 상태 문구·타일 높이 차이는 실제 화면에서 확인해야 한다.

부모 에이전트의 홈·탐색·프로필·러닝·공통 컴포넌트 diff도 별도로 검토했다. 홈은 날짜/실제 오늘 거리·횟수와 작은 승인 미니미를 함께 표시하고 시작 버튼 다음에 참가한 예정 파티·최근 실제 기록을 둔다. 탐색은 검색어가 있는 빈 결과와 원래 빈 목록의 문구를 구분한다. 프로필은 큰 외곽 카드를 제거하고 글씨 확대/좁은 폭의 미니미·설명 세로 분기를 보존한다. 러닝 안내는 기록할 거리·시간·GPS와 기기 저장을 직접 설명한다. 장식 트랙·아이콘 원형 배경·중복 홍보 문구를 제거하는 방향을 채택했다.

추가 권고로 홈 시작 버튼의 비가중 텍스트 다음에 가중 Spacer를 두면 좁은 폭/큰 글씨에서 마지막 화살표의 가용 폭이 줄 수 있다고 지적했다. 부모 에이전트가 텍스트에 가중 폭을 주고 양쪽 아이콘 폭을 먼저 예약하는 구조를 채택했다. 이는 코드의 측정 순서에 따른 개선이며 수정 전 실제 잘림을 계측한 결과가 아니다. 최종 Android 검증에는320dp/글씨200%의 ‘진행 중 러닝 보기’와 텍스트 넘침 확인을 포함하도록 했다. 프로필 카드 제거에 따른 중괄호·Adaptive 분기에는 소스상 문제를 발견하지 않았다.

설정의 반복 제목과 빈 상태의 장식 러너 아이콘도 제거했다는 부모의 후속 변경을 확인 대상으로 포함했다. 첫 빌드 성공 보고는 받았으나 마지막 CTA/설정 변경까지 포함한 최종 빌드·실행 결과를 이 단계에서 통과로 기록하지 않는다.

크루 담당의 최종 상호 검토에서 기존 탐색 화면의 `!serverConnected`만으로 연결 실패를 표시하는 조건을 추가 지적했다. 최초 조회 중인 `busy=true`에서도 실패 문구가 나올 수 있어 P0의 상태 정직성 기준에 어긋났다. 부모가 조회 중에는 `explore_loading` 진행 표시, 조회가 끝난 미연결에는 재시도 안내, 연결된 정상 빈 목록에는 빈 결과를 표시하도록 분리했다. 기존 UI 검사에도 조회 중→연결 실패→정상 빈 목록 전이를 포함하도록 바꿨다. 이 변경이 포함된 최종 실행 결과는 아래 검증 단계에서 따로 기록한다. 첫 AVD는 빌드 수정으로 부팅 도중 종료됐다는 보고이며, 앱 실행·테스트 실패 또는 성공으로 집계하지 않는다.

다음 대안은 채택하지 않았다. 보라 그라데이션을 크림색/세리프체로 일괄 교체하는 양식 변경, 전용 기능 아이콘의 이모지 교체, 모든 메타데이터의 배지화, 의미 없는 영문 소제목, 원화가 없는 의상을 완성된 이미지로 나타내는 대안이다. 기본형/포인트/기존 보유·선택 데이터는 UI 단순화 대상과 분리해 보존한다.

## 검증 상태

최종 CTA/조회 중 상태 수정까지 포함한 [debug 빌드 근거](app-review/2026-11-03-context-ui/debug-build-verification.json)를 읽었다. 오프라인·작업자1개 빌드에서 JVM45개/실패·오류·skip0, lint오류0/경고35다. debug/test APK 컴파일·JVM/lint 결과이며 Android 실행·release 서명·실기기 결과로 바꾸지 않는다.

부팅 완료한 전용 클라우드 AVD의 앱 설치/실행 전 전체 화면에서 System UI 응답 없음 안내가 관찰됐고, 부모가 실제 팝업의 Wait를 선택했다. 앱 ANR·원인 해결로 해석하지 않는다. 이번 묶음의 Android 실행·새 화면 검사 결과는 실제 완료 후 추가한다. 수치 검사를 시각 승인으로 해석하지 않으며 사용자 시각 승인은 아직 받지 않았다. 승인된 미니미 원본·원화 준비 범위와 과거 APK 출처를 바꾸지 않는다.

첫 fixture 실행 중 `fiveTabsOpenTheirActualScreens`에서 고정 시작 버튼에 `performScrollTo`를 적용해 “부모 Scroll SemanticsAction 없음” 오류가 보고됐다. 고정 버튼은 스크롤 부모가 없으므로 화면 표시를 직접 확인하도록 검사만 교정하는 것이 맞다. 이 실패를 앱 결함이나 전체 통과로 바꾸지 않는다. 최초 원시 결과를 보존하고 영향받은 검사만 다시 실행한 결과를 후속 기록한다.

### 첫 Android 화면의 독립 검토

첫 fixture 원시 보고서 `ui-flow-and-responsive-fixtures.txt`는10개 실행/실패1개/통과9개,248.469초다. 실패는 위 고정 버튼 스크롤 검사이며 단일10/10 성공으로 표시하지 않는다. `fixture-home-360-100`, `fixture-consumer-closet-native-items`, `fixture-rooms-list-320-200`, `fixture-rooms-crew-detail-320-200`, `fixture-home-320-200` PNG를 직접 확인했다.

- 일반 홈은 실제 기록 상태·승인 미니미·시작 행동의 순서가 명확하다. 옷장은 준비된 기본형과 미준비 상태를 구분하면서 이전의 큰 공통 행거·제목 빈 공간이 줄었다.
- 320dp/글씨200% fixture 홈의 버튼은 보이지만 ‘러닝 시작하’ 다음 줄에 ‘기’가 한 글자로 분리됐다. 실제 시각 관찰에 따른 P1 가독성 권고이며 버튼 잘림을 계측한 것은 아니다. 큰 글씨에서 ‘러닝 시작’/‘러닝 보기’처럼 의미가 유지되는 짧은 라벨을 검토하도록 전달했다.
- 크루 상세의 제목 위쪽이 화면 밖에 있는 사진은 목록으로 스크롤한 뒤 수집한 상태다. 해당 사진만으로 제목 잘림 회귀라고 판정하지 않는다. 실제 native320dp/글씨200% 홈의 전체 버튼과 하단 탐색/viewport 경계는 별도로 확인해야 한다. `assertIsDisplayed`만으로 버튼 전체 노출을 입증하지 않는다.

새 실제 MainActivity/로컬HTTP의 홈·크루 목록·크루 상세·파티 상세·파티 채팅·여자 무료 선택 옷장6장도 직접 확인했다. 파일명이 `mainactivity-native-*.png`인6개의 SHA256은 모두 서로 달랐고, 해당 사진에는 System UI 팝업이나 다른 화면 혼입이 보이지 않았다. 크루 상세의 두 파티는 시간·거리·페이스·인원을 행으로 비교할 수 있고, 옷장은 민트 반팔의 선택 체크/선택 보관·미리보기 준비 중 안내와 여자 기본형 표시가 함께 확인된다. `mainactivity-local-http.txt`의1개 검사76.56초 통과도 읽었다. 이는 로컬HTTP/debug 앱 실행 결과이며 운영 Firebase·공개 서명 APK·실제 휴대폰/Google 성공으로 바꾸지 않는다. 파티 상세에는 HTTP 경로의 음성 카드가 있으므로 기본 Firebase 대표 갤러리에서 제외하는 것이 맞다. 홈/옷장의 스크롤 하단 안내가 viewport 밖에 있는 것을 잘림 결함으로 해석하지 않는다.

### 실제 native320dp/글씨200%에서 발견한 세로 문제

`native-320dp-font2-home-active-native-320-font2-device.png` 전체 기기 사진을 별도로 직접 확인했다. 진행 중 홈의 큰 날짜·제목·오늘 기록 안내 아래에 놓인 시작 버튼은 하단 둥근 경계가 탐색 막대에서 잘려 보인다. 버튼 텍스트가 보이고 `assertIsDisplayed`가 통과해도 전체 버튼 노출을 보장하지 않는 실제 사례다. 가려진 높이나 수정 전 버튼의 전체 좌표는 이 사진만으로 산정하지 않는다.

부모가 큰 글씨에서만 제목/작은 미니미로 헤더를 압축하고 날짜를 생략하며 오늘 실제 요약을 버튼 뒤로 이동하는 수정을 채택했다. 버튼 라벨은 큰 글씨에서 ‘러닝 시작’/‘러닝 보기’로 줄이고 일반 글씨의 표현은 유지한다. 실제 버튼 bottom과 하단 홈 탭 top을 같은 root 좌표로 비교하는 검사를 보강하고 최종 APK로 다시 실행하기로 했다. 앞서 정상으로 보인 일반 글씨6장과 이 세로 문제를 구분한다.

검토자는 클립된 `boundsInRoot`만 비교하면 같은 거짓 통과가 생길 수 있다고 추가 지적했다. 최종 검사 소스는 공개 `getUnclippedBoundsInRoot` API를 사용해 전체 버튼/탭 경계를 같은 root의 dp 단위로 비교하고 `home-action-unclipped-native-320-font2.json`에 단위를 명시한다. 큰 글씨 헤더/라벨 수정과 이 검사 소스를 다시 읽었으며 컴파일 성공과 실제 좌표·사진 확인은 구분한다.

`navigation-label-baselines-native-320-font2.txt`의 하단5라벨 baseline은 모두801px/차이0px다. 이는 해당 라벨 정렬의 실측이며 홈 버튼의 세로 노출이나 다른 화면의 전체 적합성을 증명하지 않는다. 중간 native 검사의 통과와 이번 시각 결함·최종 수정 후 결과도 별도로 보존한다.
