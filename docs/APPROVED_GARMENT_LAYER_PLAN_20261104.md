# 승인 원본의 의복 레이어 다음 단계

2026-11-04 한국 시간.0.3.2 기록/계정 작업과 독립적으로 검토한 F03 구현 계약이다. **새 의복·마스크·컬러 실착을 완성한 문서가 아니다.** 이미지 생성·편집·Aseprite 실행은 하지 않았다.

## 확인한 출발점

- 승인 원본 `docs/design/avatars/v0.3.0/running-motion-art-source.png`, 앱 번들 `app/src/main/assets/avatars/v0.3.0/running-motion.png`, 검토용 사본의 SHA256이 모두 `f9035f29ced0c7ba513dfe24cb727410a7204dc482fc457e806c7a9b3cdbfa65`와 일치한다.2048×768/남녀2행×8프레임/셀256×384다.
- 현재 앱은 원본 셀을 직접 표시한다. 기존 `GarmentPalette`의 마스크 밖 불변·명암 보간은 재사용할 수 있지만 현재 의복 마스크는 미승인 수영복용이다. 승인 러닝복에 대입하면 몸/팔/피부의 위치가 맞지 않는다.
- 원본 alpha는 읽기 검사에서0..254였다. 원본의 alpha255만 의복으로 고르는 구현은 잘못이다. 마스크 자체의 alpha255 라벨 인코딩과 원본의 투명도는 다른 계약이다.
- 기존 top/bottom의 ID는 반팔·긴팔·브라탑·타이츠 등 **형태**를 나타낸다. 기본형의 색상만 바꾸어 해당 아이템 원화가 완성됐다고 표시하지 않는다.58ID/13슬롯/9탭·기존 보유권/포인트/저장과 액세서리 점유 규칙을 보존한다.

## 가장 작은 실제 변경 범위

1. 승인 원본의 **기본 상의·하의·신발 천 색상**을 독립 선택하는 프레임별 마스크부터 만든다. 기본형 얼굴·체형·팔/다리·현재 의복 형태는 그대로 둔다.
2.2048×768 고정 좌표에서16셀 각각을 검토한다. 원본과 같은 크기의 명시적 의복 라벨·명암 마스크와 별도 보호 영역, source/mask SHA·버전·라벨 설명 manifest를 사용한다.
3. 피부·얼굴·머리·눈·윤곽선·신발 밑창과 의복 마스크의 교집합은0이어야 한다. 팔이 옷 앞을 지나는 프레임은 팔을 보호하고 보이는 천만 마스킹한다. 기존 수영복 다각형을 이동/복사해 대신하지 않는다.
4. 새 API는 기본 러닝복의 영역명을 명시하고 기존 수영복 API를 보존한다. 원본 배열을 복사한 뒤 마스크 안의 픽셀만 명암 팔레트로 바꾼다. 원본색 선택은 원본과 전체ARGB가 같아야 한다.
5. 색상 설정과 형태 아이템 선택을 분리한다. 초기 로컬 설정으로 시작하면 다른 러너/기기 동기화가 되지 않는 경계를 표시한다. 장기 공통 AvatarStyle 변경은 기존JSON 누락 기본값·서버 허용 필드·프로필 저장까지 함께 검증한다.
6. 마스크 없음/해시 불일치/잘못된 라벨이면 색상 기능을 활성화하지 않고 승인 원본을 표시한다. 완성된 것처럼 안내하지 않는다. 캐시는 성별·프레임·색상·마스크 버전을 구분하고 크기를 제한한다.

- [ ]7→0 연결·8프레임의 색 깜빡임/누락 확인. 원본 양팔 움직임 자체의 품질 보정과 구분.
- [ ] 홈·옷장·지도, 저장/재실행·남녀 전환·초기화 결과 일치와 실제 Android 사진 확보.

다른 형태의 옷을 입히려면 원본에 없는 가려진 피부·천·머리 뒤의 프레임별 원화가 필요하다. 피부색으로 옷을 덮거나 거절된v0.4 관절 부품을 다시 조립하지 않는다. 수영복은 별도 미승인 시안/검토이며 비키니 상하 독립색도 해당 원화의 명시 마스크를 사용한다.

`AGENTS.md`는 미승인 결과를 승인/실제 앱 실행으로 표시하지 말라고 명시한다. 모든 컬러 준비 작업에 사전 확인을 요구하는 포괄 규정은 없다. 따라서 마스크 제작/엔진 검수 준비는 사용자 응답 대기로 멈출 필요가 없으며, 실제 준비된 결과를 만든 뒤 시각 검토를 받는다.
