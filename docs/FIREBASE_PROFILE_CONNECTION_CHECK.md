# 프로필 연결 권한 오류 확인

0.4.1 휴대폰에서 보고된 권한 팝업을 위한 점검이다. 0.4.2는 서버의 닉네임 저장 확인 전 연결을 완료하지 않고, 실패 시 같은 계정·입력으로 다시 시도한다. 앱 수정과 운영 권한은 별개다. 이번 변경은 Firestore 규칙을 새로 바꾸지 않는다.

1. [runmoni-3c08e의 Firestore Rules](https://console.firebase.google.com/project/runmoni-3c08e/firestore/rules)를 연다. 현재 **게시된** 규칙에 `match /communityNicknames/{key}`와 `communityProfiles`의 닉네임 예약 검사가 있는지 확인한다. 편집 중인 초안과 게시 버전을 구분한다.
2. 해당 경로가 없다면 저장소 [전체 규칙](../firebase/firestore.rules)을 Rules 편집기에 반영하고 게시한다. 일부 경로를 공개 허용하거나 `allow read, write: if true`로 우회하지 않는다. 이전 크루/파티 권한과 위치 공유 제한도 포함된 전체 파일이다. 이미 동일 규칙이라면 다시 게시할 필요가 없다.
3. 새 APK를 기존 앱 위에 업데이트 설치하고, 같은 닉네임으로 프로필 연결을 재시도한다. 앱 삭제/데이터 초기화/새 익명 계정 생성으로 기존 UID를 바꾸지 않는다. 연결 후 창 닫힘·이름 유지·크루 접근을 확인한다. 이름이 이미 사용 중이라는 안내는 권한 오류와 다른 결과다.
4. 최신 규칙에서도 실패하면 화면에 표시된 안내와 Rules 게시 시각을 확인한다. 프로젝트가 다른 경우 연결된 Android/Firebase 설정부터 대조한다. 이 점검에는 키·토큰·비밀번호를 채팅에 보낼 필요가 없다.

현재 클라우드에는 운영 Firebase 관리 인증이 연결되어 있지 않아 Rules의 실제 게시 버전과 운영 쓰기 성공을 직접 확인하지 못했다. 로컬 demo Rules/Android SDK 검사와 휴대폰·운영 Google 로그인 결과는 각각 별도 근거다. 과거 사용자의 게시 완료 보고를 취소하거나 현재 규칙이 낡았다고 단정하지 않는다.
