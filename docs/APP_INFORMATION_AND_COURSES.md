# 앱 정보·업데이트·코스 구성 결정 — 2026-10-25

## 앱 정보

‘나 → 앱 정보’의 버전 카드는 실제 설치 versionName/versionCode를 표시한다. 설정 화면에서도 같은 페이지로 접근한다. 버전 선택 시 변경 내역을 보며, 더 새로운 호환 서명 APK가 확인됐으면 다운로드 확인창을 먼저 제시한다.

| 상태 | 표시·동작 |
|---|---|
| 확인 전 | 설치 버전 + 업데이트 확인 안내. 최신이라고 단정하지 않음 |
| 확인 중 | 진행 상태, 중복 요청 방지 |
| 새 공개 APK의 versionCode가 큼 | 버전 카드 상단 레드닷 + ‘새 버전’ 텍스트. 선택 → 업데이트 확인 → 외부 APK 다운로드 |
| 설치본이 공개본과 같거나 개발 버전이 앞섬 | 확인한 공개 버전 표시. 개발본과 공개본을 동일시하지 않음 |
| 오프라인·실패 | 실패 설명과 재확인. 이전에 확인한 새 버전 정보는 유지 |

업데이트는 GitHub의 `updates/android.json`에 기록한 **게시 검증을 마친 릴리스 정보만** 자동 확인한다. 기본 6시간 캐시, 수동 재요청은 30초 간격, 동시 요청 1개, 응답 상한 32KiB다. 정식·개발 채널에서 숫자 versionCode가 가장 큰 호환 버전을 선택한다. APK 본문을 자동 다운로드하지 않는다. 패키지·버전·서명 인증서·크기·해시 형식·고정 저장소 URL을 검증하며, 실제 내려받은 APK 무결성·설치 서명 확인은 별도 단계다. 개발 프리뷰는 preview도 확인하고 일반 정식 버전은 stable만 대상으로 한다. GitHub APK 게시 전 개발 빌드를 업데이트 피드에 먼저 넣지 않는다.

버전 번호를 문자열로 비교하지 않는다. `versionCode`를 비교하므로 0.10과 0.9의 사전식 비교나 오래된 prerelease를 최신으로 잘못 표시하는 문제를 피한다. 자동 설치·권한 우회·강제 업데이트는 제공하지 않는다.

같은 페이지에 아이콘을 붙인 대시보드·GitHub·오픈소스/SDK 고지·문제 신고를 둔다. 문제 신고는 앱 버전과 Android API를 채운 GitHub 작성 화면만 열며 직접 전송하지 않는다. 계정·좌표·토큰을 자동 첨부하지 않는다.

## 마일리지

현재 용도는 미니미 꾸미기 전용 포인트다. 현재 모드에 따라 기기 지갑 또는 초대 파일럿 서버 지갑을 사용한다. 기본 환산은 10m당 1P = 1km당 100P로, 5km = 500P, 10km = 1,000P다. 서버의 실제 지급량은 GPS 검증과 설정 가능한 일일 상한의 영향을 받는다(서버 기본 설정 10,000P, 원격 실제 설정은 미확인). 앱의 마일리지 영역에서 설명 페이지와 옷장으로 연결한다. Google 요약 백업은 포인트·아이템을 저장하지 않으며 두 지갑은 자동 합산되지 않는다.

포인트를 앱의 주요 목표로 과도하게 강조하지 않는다. 실제 러닝 기록·꾸미기 보상 순서로 표현하고, 현금·출금·유료 구매 기능이 있는 것처럼 보이지 않게 한다. 파일럿 서버에는 원장·중복 구매 방지·GPS 검증이 이미 구현되어 있다. Google 계정 기반 기기간 아이템 소유권에는 이 원장과 Firebase UID의 연결·기기 지갑과의 관계·계정 복구를 추가로 구현하고 검증해야 한다.

## 코스와 크루·파티의 관계

사용자가 ‘내 코스 + 작성자가 명시적으로 공개에 동의한 코스 탐색’을 선택했다. 후속 질문에서 **이번 작업은 디자인·앱 정보·업데이트를 먼저 완성하고 코스는 설계만 확정**하는 범위로 결정했다. 코스 저장·공개·파티 브리핑은 이후 별도 구현 대상이다. 비공개 GPS 기록이나 현재 8필드 Firebase 요약을 공개 경로 데이터로 사용하지 않는다.

| 개념 | 책임 | 앱 위치 |
|---|---|---|
| 코스 | 반복해서 사용할 경로·거리·고도·노면·공개 상태 | 탐색의 ‘코스’, 개인 코스 목록 |
| 크루 | 지속적인 사람 모임. 여러 코스를 가질 수 있음 | 크루의 모임·기본 코스 |
| 파티 | 날짜가 있는 함께 달리기 1회 | 오늘의 코스·브리핑·참가자·음성 |
| 실시간 위치 | 별도 동의한 참가자의 현재 상태 | 실행 중 파티의 코스 위 표시 |

‘크루는 항상 같은 코스를 뛰는 모임’으로 데이터 모델을 고정하지 않는다. 같은 크루가 오늘은 3km, 다음 주는 10km를 선택할 수 있어야 한다. 크루 기본 코스를 지정하더라도 파티가 당시 코스 버전을 참조해 이후 코스 수정으로 약속한 경로가 바뀌지 않게 한다.

## 벤치마크와 런모니 적용

- [Strava Community Routes](https://support.strava.com/en-us/articles/15401756-how-do-community-routes-on-strava-work): 지도에서 코스를 탐색하고 경로 공개를 제어하는 흐름을 참고한다. 타 서비스의 데이터를 무단 수집하는 계획은 아니다.
- [Garmin 이전 활동으로 코스 만들기](https://support.garmin.com/en-IN/?faq=tWx3JQyjlU474jqa91EJs8): 활동 기록과 다시 사용할 코스의 개념을 구분한다.
- 런모니는 탐색에서 개인·공개 코스를 찾고, 파티에 코스를 선택한 뒤 브리핑하는 방향으로 구성한다. 추천 거리·난도·인기도는 데이터가 실제 존재할 때만 계산한다. 데이터 없는 ‘인기 코스’를 샘플로 채우지 않는다.

## 코스 브리핑 제안

파티 상세의 ‘오늘의 코스’에 경로, 총거리, 예상 시간, 모이는 지점, 출발 시각, 목표 페이스, 쉬는 지점, 화장실·급수와 주의 구간을 둔다. 검증되지 않은 급수·화장실은 확인 날짜와 작성자 정보 없이 보장하지 않는다. 시작 전에는 브리핑, 시작 후에는 같은 코스 위 참가 위치와 경로 이탈 상태를 우선한다.

현재 Android 기록 모델에는 고도·노면 정보가 없으므로 상승 고도나 경사 기반 난도를 임의로 만들지 않는다. 서버에는 선택적 altitude_m 필드가 있지만 현재 Android 기록에서 수집·보관한 고도라는 증거는 아니다. 예상 시간은 선택한 목표 페이스 × 코스 거리로 계산한 추정값임을 구분한다. 고도·노면·편의시설은 신뢰 가능한 별도 데이터가 준비됐을 때 추가한다.

- 공개 탐색 지도: 크루 대표 미니미와 집계 숫자 중심. 무제한 사용자 아이콘을 한 화면에 그리지 않음.
- 실행 중 파티 지도: 현재 파일럿 최대 20명 안에서 위치 공유에 동의한 참가자만 표시. 기존 15초 게시·45초 만료 규칙을 유지하고 ‘방금’처럼 오해하지 않게 갱신 경과를 표시.
- 리더·페이서·후미 역할을 구분하면 한 팀으로 달리기 쉽다. 음성·음악·GPS 기록과 위치 공유를 서로 독립적으로 켜고 끌 수 있어야 함.

## 공개 경로의 필수 경계

개인 원본과 공개 코스를 별도 저장한다. 공개 시 경로 미리보기와 명시적 확인, 시작·종료 주변 숨김 영역, 공개 취소·삭제·신고를 제공한다. 숨김 구간을 지운 뒤 남은 두 지점을 직선으로 이어 위치를 추정하게 만들지 않는다. timestamps와 계정별 이동 원본은 공개 코스에 포함하지 않는다. 숨김 처리만으로 거주지 추정을 완전히 막는다고 보장하지 않는다.

공개 코스의 조회량·완주 횟수는 공개에 동의한 기록에서만 집계한다. 작성자의 독립 공개 동의 없이 ‘많이 뛴 코스’ 추천을 생성하지 않는다. 코스 추천·파티 참가·현재 위치 공유는 3개의 독립 선택이다.

이번 문서는 확정한 제품 구분과 구현 경계이며, 코스 저장·공개 API나 실시간 코스 브리핑이 이미 배포됐다는 뜻은 아니다. 구현 여부와 시험 결과는 CHANGELOG와 VALIDATION에 별도로 기록한다.
